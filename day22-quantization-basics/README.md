# Day 22: 量化基础 — 从 FP16 到 INT4 的数学之旅

## 🔗 上节回顾

昨天我们学习了 QLoRA，用 NF4（正态分布优化的 4-bit 格式）把 7B 模型从 14GB 压到 3.5GB，效果只损失 1-3%。QLoRA 里用到了"量化"这个概念——存储用 4-bit，计算时反量化到高精度。但我们没有深入回答一个根本问题：**量化到底是怎么做到"压缩这么狠但效果几乎不变"的？** 今天我们就来彻底搞懂量化的数学原理，手写线性量化器，亲眼看看精度损失到底有多大。

## 🌡️ 第一个问题：精度是什么？为什么能"砍掉"？

> ❓ **问题**：一个 FP16 的浮点数到底长什么样？砍掉一半位之后会发生什么？

在讲量化之前，我们必须先理解"精度"到底在说什么。

### 浮点数的存储结构

一个浮点数由三部分组成：**符号位（sign）+ 指数位（exponent）+ 尾数位（mantissa）**。

```
FP32（32 位）：
┌───────┬──────────────┬───────────────────────────────┐
│ sign  │  exponent(8) │      mantissa(23)             │
│ 1 bit │  8 bits      │      23 bits                  │
└───────┴──────────────┴───────────────────────────────┘
能表示的范围：±3.4 × 10³⁸
有效数字：约 7 位十进制

FP16（16 位）：
┌───────┬──────────────┬─────────────────┐
│ sign  │  exponent(5) │  mantissa(10)   │
│ 1 bit │  5 bits      │  10 bits        │
└───────┴──────────────┴─────────────────┘
能表示的范围：±6.5 × 10⁴
有效数字：约 3 位十进制

BF16（16 位）：
┌───────┬──────────────┬─────────────────┐
│ sign  │  exponent(8) │  mantissa(7)    │
│ 1 bit │  8 bits      │  7 bits         │
└───────┴──────────────┴─────────────────┘
能表示的范围：±3.4 × 10³⁸（和 FP32 一样！）
有效数字：约 2 位十进制
```

关键观察：**BF16 牺牲了精度（尾数只有 7 位），但保留了 FP32 的范围（指数 8 位）**。为什么？因为训练时梯度可能非常大或非常小，范围比精度更重要。

### 类比：精度就像照片的像素

```
FP32 = 4K 超高清照片（每个细节都清清楚楚）
FP16 = 1080P 高清照片（细节略少，但看起来几乎一样）
BF16 = 1080P 但用了更强的 HDR（色彩范围大，但细节少一点）
INT8 = 720P 视频（明显粗糙，但主要内容还在）
INT4 = 480P 视频（很多细节丢失，但还能看出是什么）

关键洞察：
照片从 4K 压缩到 1080P，文件小了一半，但大部分情况下你看不出区别
模型权重从 FP32 压缩到 INT8，存储小了 4 倍，但效果可能只差 1%
```

### 那为什么权重能压缩而几乎不失精度？

这就触及了量化的核心洞察——**神经网络权重不是随机分布的**。

```
如果权重均匀分布在 [-100, 100]：
  → 你需要很高的精度来区分 3.14159 和 3.14160
  → 压缩会造成严重损失 ❌

但实际权重的分布：
  → 绝大部分集中在 [-0.5, 0.5] 附近，像一座尖尖的山峰（正态分布）
  → 远离 0 的权重非常少
  → 就像一座城市：市中心人口密集（需要精细管理）
    郊区人少（不需要那么精细）

这就是为什么 INT8 甚至 INT4 能工作：
  → 量化级别集中分布在权重密集的区域
  → 稀疏区域的精度损失不影响整体效果
```

## 📐 线性量化：最朴素的压缩方式

> ❓ **问题**：怎么把一个连续的浮点数"塞进"有限的整数格子里？

线性量化是最基础也最直观的方法。核心思想：**找一个线性映射，把浮点范围映射到整数范围**。

### 数学公式

```
给定一个权重张量 W，要量化到 [qmin, qmax] 范围（如 INT8 的 [-128, 127]）：

步骤 1：找范围
  W_min = min(W)
  W_max = max(W)

步骤 2：算缩放因子 scale
  scale = (W_max - W_min) / (qmax - qmin)

步骤 3：算零点 zero_point
  zero_point = qmin - round(W_min / scale)

步骤 4：量化
  Q = clamp(round(W / scale) + zero_point, qmin, qmax)

步骤 5：反量化（恢复）
  W_hat = (Q - zero_point) × scale

其中 clamp(x, a, b) = max(a, min(b, x))，把值限制在范围内
```

### 具体例子

```
假设有一个权重矩阵 W = [[0.3, -1.2], [2.1, 0.05]]

量化到 INT8（范围 [-128, 127]）：

1. 找范围：
   W_min = -1.2, W_max = 2.1

2. 算缩放：
   scale = (2.1 - (-1.2)) / (127 - (-128)) = 3.3 / 255 ≈ 0.01294

3. 算零点：
   zero_point = -128 - round(-1.2 / 0.01294) = -128 - (-93) = -35

4. 量化：
   W[0,0] = round(0.3 / 0.01294) + (-35) = round(23.2) - 35 = 23 - 35 = -12
   W[0,1] = round(-1.2 / 0.01294) + (-35) = round(-92.7) - 35 = -93 - 35 = -128
   W[1,0] = round(2.1 / 0.01294) + (-35) = round(162.3) - 35 = 162 - 35 = 127
   W[1,1] = round(0.05 / 0.01294) + (-35) = round(3.9) - 35 = 4 - 35 = -31

5. 反量化（验证）：
   W_hat[0,0] = (-12 - (-35)) × 0.01294 = 23 × 0.01294 = 0.2976  （原始 0.3，误差 0.0024 ✅）
   W_hat[1,0] = (127 - (-35)) × 0.01294 = 162 × 0.01294 = 2.0963 （原始 2.1，误差 0.0037 ✅）
```

### 量化误差的本质

从上面的例子可以看出：

```
量化误差 = |W - W_hat|
         = |W - (Q - zero_point) × scale|
         = |W - round(W/scale + zero_point) × scale + zero_point × scale|
         ≈ |W - round(W/scale) × scale|

最大误差 ≤ scale / 2

所以：
  scale 越小 → 误差越小
  scale = (W_max - W_min) / (qmax - qmin)
  
  要让 scale 小，要么：
  1. 减小 W_max - W_min（让权重范围更窄）→ 这就是为什么权重的正态分布对量化友好
  2. 增大 qmax - qmin（用更多 bit）→ INT8 比 INT4 精度高
```

## 📦 两种量化模式：对称 vs 非对称

> ❓ **问题**：上面说 zero_point 可能不为 0，但很多实际系统喜欢让 zero_point = 0，为什么？

这是线性量化的两种主要变体：

### 对称量化（Symmetric）

```
特点：zero_point = 0，范围关于 0 对称

INT8 对称量化：范围 [-127, 127]（注意不是 [-128, 127]，为了让两边对称）

scale = max(|W_max|, |W_min|) / 127
Q = clamp(round(W / scale), -127, 127)
W_hat = Q × scale

优点：
  ✅ 简单，不用存 zero_point
  ✅ 反量化只需一次乘法
  ✅ 硬件友好（整数乘法 + 位移）

缺点：
  ❌ 如果权重偏向一侧（比如全在 [0, 1]），会浪费一半的表示范围
  
类比：
  对称量化 = 一把两端等长的天平
  → 天然适合"两边差不多重"的情况
  → 但如果一边总是更重，另一边的空间就浪费了
```

### 非对称量化（Asymmetric）

```
特点：zero_point 不一定为 0，范围可以偏移

scale = (W_max - W_min) / (qmax - qmin)
zero_point = clamp(round(qmin - W_min / scale), qmin, qmax)
Q = clamp(round(W / scale) + zero_point, qmin, qmax)
W_hat = (Q - zero_point) × scale

优点：
  ✅ 充分利用全部量化级别
  ✅ 对偏移分布（如 ReLU 后的激活值全为正）效果更好

缺点：
  ❌ 要额外存储 zero_point
  ❌ 反量化需要减法和乘法
  ❌ 某些硬件不支持非对称量化

类比：
  非对称量化 = 一把可以从任意位置开始量的卷尺
  → 更灵活，但操作稍微复杂
```

### 怎么选？

```
权重（Weights）：通常用对称量化
  → 权重是静态的，分布比较规律
  → 而且权重经常接近正态分布（关于 0 对称）

激活值（Activations）：取决于激活函数
  → ReLU 后的激活全为正 → 非对称更好
  → 没有固定模式的激活 → 两种都可以

实际推理框架的选择：
  ONNX Runtime → 默认对称
  TensorRT     → 权重对称，激活非对称
  TFLite       → 两种都支持
```

## 🧱 逐张量量化 vs 逐通道量化

> ❓ **问题**：刚才我们对整个矩阵找 min/max，但如果不同通道的分布差异很大呢？

这引出了一个重要的粒度选择：

### 逐张量量化（Per-Tensor）

```
整个矩阵共享一组 scale 和 zero_point

例如一个 4096×4096 的权重矩阵：
  只需要 1 个 scale + 1 个 zero_point

问题：
  如果某一行/通道的权重范围是 [-0.1, 0.1]
  另一行/通道的范围是 [-5.0, 5.0]
  
  整个矩阵的 scale = 10.0 / 255 ≈ 0.039
  
  [-0.1, 0.1] 的那行 → 量化到大约 [-3, 3] → 只用了 6 个级别 → 精度很低！
  [-5.0, 5.0] 的那行 → 量化到大约 [-128, 128] → 用了全部级别 → 精度还行

类比：
  一栋楼里所有人共用一个空调温度设定
  → 有人觉得热，有人觉得冷
  → 大部分人都不舒服
```

### 逐通道量化（Per-Channel）

```
每一行（输出通道）有自己的 scale 和 zero_point

4096×4096 的权重矩阵：
  需要 4096 个 scale + 4096 个 zero_point
  
  [-0.1, 0.1] 的通道 → scale ≈ 0.0008 → 量化精度高 ✅
  [-5.0, 5.0] 的通道 → scale ≈ 0.039 → 量化精度高 ✅
  每个通道都得到了"量身定制"的量化

代价：
  额外存储 4096 × 2 = 8192 个参数（相比 16M 的权重，微不足道）

效果：
  INT8 逐通道量化的精度损失通常 < 0.5%
  INT8 逐张量量化的精度损失可能 > 2%
```

### 逐组量化（Per-Group）

```
按固定大小的组来量化，折中方案

例如 GPTQ 用的 group_size = 128：
  每 128 个权重共享一组 scale 和 zero_point
  
  4096×4096 的矩阵：
  组数 = 4096 × 4096 / 128 = 131072 组
  额外参数 = 131072 × 2 = 262144（占权重的 1.6%）

这是 QLoRA (NF4) 使用的方式：
  block_size = 64（QLoRA 论文默认值）
  → 精度和存储的良好平衡
```

## ⚡ 训练后量化（PTQ）：最实用的量化方式

> ❓ **问题**：量化模型需要重新训练吗？能不能直接"压"一个已有的模型？

**训练后量化（Post-Training Quantization, PTQ）**就是答案——不需要重新训练，直接压缩已有的 FP16/BF16 模型。

### 动态量化（Dynamic Quantization）

```
流程：
  1. 权重提前量化为 INT8（静态）
  2. 激活值在推理时"临时"量化（动态）
  3. 用 INT8 做矩阵乘法
  4. 输出反量化回 FP32

优点：
  ✅ 不需要校准数据（calibration data）
  ✅ 实现最简单
  ✅ PyTorch 一行代码：torch.quantization.quantize_dynamic(model, {nn.Linear}, dtype=torch.qint8)

缺点：
  ❌ 激活值的量化/反量化有运行时开销
  ❌ 激活值的量化精度不如静态方法（因为没有提前统计范围）

类比：
  动态量化 = 随身带一把量角器，需要时才量
  → 灵活但慢一点，精度一般
```

### 静态量化（Static Quantization）

```
流程：
  1. 权重量化为 INT8（静态）
  2. 用校准数据集（几百个样本）跑一遍推理，统计每层激活值的范围
  3. 根据统计结果，把激活值的 scale/zero_point 也提前算好
  4. 推理时全程 INT8

优点：
  ✅ 推理速度最快（全程整数运算）
  ✅ 精度通常最好

缺点：
  ❌ 需要校准数据
  ❌ 实现更复杂

类比：
  静态量化 = 提前量好所有尺寸，到时候直接用
  → 需要前期准备，但后续最快最准
```

### 校准数据的作用

```
为什么静态量化需要校准数据？

因为激活值的范围取决于输入数据：
  输入 "你好" → 第一层激活范围可能是 [-2, 3]
  输入 "Hello" → 第一层激活范围可能是 [-1, 5]

如果只用一个样本的激活范围来量化：
  → 可能遗漏极端值 → 推理时溢出 ❌

校准数据的作用：
  跑几百个有代表性的样本
  → 统计每层激活值的 max 和 min
  → 取合适的范围（通常用 99.9% 分位数，不要被极端值影响）
  → 这个范围用于后续所有推理

类比：
  你要给一条河修堤坝，不能只看一天的水位
  → 要观测一年，统计最高水位
  → 堤坝高度按历史最高水位来设计
```

## 🧪 量化感知训练（QAT）：精度最高的方式

> ❓ **问题**：如果 PTQ 的精度损失不可接受怎么办？有没有办法让模型"适应"量化？

**量化感知训练（Quantization-Aware Training, QAT）**——在训练时就"假装"自己在用低精度，让模型学会适应量化误差。

### 伪量化（Fake Quantization）

```
QAT 的核心技巧：

前向传播时：
  FP32 权重 → 伪量化（量化后立即反量化）→ 带量化噪声的 FP32 权重 → 正常计算

反向传播时：
  梯度正常计算（STE - Straight-Through Estimator）
  round() 的梯度为 0，直接"穿透"过去

伪量化的效果：
  W_quantized = (round(W / scale) + zero_point) × scale - zero_point × scale
  
  等价于给权重加了一个噪声：
  W_noisy = W + ε，其中 ε ≈ [-scale/2, scale/2]

  模型在训练中就"习惯了"这个噪声
  → 真正量化时，误差不会让它措手不及

类比：
  PTQ = 你一直在安静环境练琴，突然到嘈杂的舞台上表演
        → 可能因为环境变化而发挥失常

  QAT = 你从一开始就在嘈杂环境练琴
        → 已经习惯了噪音，上台后发挥如常
```

### STE（Straight-Through Estimator）

```
问题：round() 不可导，怎么反向传播？

解决：STE 的近似
  前向：y = round(x)（真正的量化）
  反向：∂L/∂x ≈ ∂L/∂y（假装 round() 的导数是 1）

  就像：你不知道楼梯的具体坡度（不可导）
        但你知道方向是对的（梯度可以穿过）
        所以就直接走过去

虽然不精确，但实践中效果非常好
几乎所有 QAT 方法都用 STE
```

### PTQ vs QAT 对比

```
                 PTQ（训练后量化）        QAT（量化感知训练）
───────────────────────────────────────────────────────────
需要训练？       ❌ 不需要                 ✅ 需要额外训练
需要数据？       ✅ 少量校准数据            ✅ 训练数据
实现难度         低                        中
推理精度         INT8 好用，INT4 有损       INT4 也能保持较好精度
适用场景         快速部署、大模型           追求极致精度、小模型

实际选择：
  大多数 LLM 部署 → PTQ（大模型本身精度冗余多，PTQ 就够了）
  边缘设备/小模型 → QAT（小模型对精度更敏感，QAT 更保险）
```

## 🔢 深入理解 INT4 量化：到底丢了多少信息？

> ❓ **问题**：INT4 只有 16 个级别，用来表示几十亿个权重，真的够用吗？

让我们用一个具体的实验来回答：

### 一个模拟权重分布的量化实验

```
假设 1000 个权重，服从正态分布 N(0, 0.3)（典型的神经网络权重分布）

INT8 量化（256 个级别）：
  scale ≈ 0.0024
  最大误差 ≈ 0.0012
  平均误差 ≈ 0.0006
  → 几乎无损 ✅

INT4 量化（16 个级别）：
  scale ≈ 0.040
  最大误差 ≈ 0.020
  平均误差 ≈ 0.010
  → 有一定误差，但对整体模型影响不大 ✅

INT2 量化（4 个级别）：
  scale ≈ 0.20
  最大误差 ≈ 0.10
  平均误差 ≈ 0.05
  → 误差太大，通常不可用 ❌

为什么 INT4 "够用"？
  1. 模型有冗余——7B 参数里很多是"凑数"的，丢一点精度不影响大局
  2. 量化误差是随机分布在所有参数上的
     → 就像一张照片每个像素都偏了一点点
     → 整体看起来几乎没变
  3. 逐通道/逐组量化让每个局部都有"量身定制"的 scale
     → 大大缓解了"用 16 个级别表示一切"的限制
```

### 信息论视角

```
一个 FP16 权重携带 16 bit 信息
一个 INT4 权重携带 4 bit 信息

但"信息"不等于"有用信息"：
  FP16 的 16 bit 中，很多是"噪声"（训练时的随机波动）
  真正决定模型行为的可能只有 4-6 bit 的"信号"

类比：
  一段 1080P 视频，每个像素 24 bit 颜色
  但人眼只能分辨大约 1000 万种颜色（约 23 bit）
  实际上有意义的颜色信息可能只有 6-8 bit
  
  所以把 24 bit 压缩到 8 bit，人眼几乎看不出区别
  神经网络权重同理：16 bit 压到 4 bit，性能损失很小
```

## 📊 量化对模型性能的实际影响

> ❓ **问题**：说了这么多理论，量化到底会让模型变差多少？

### 各精度等级的典型表现

```
以 LLaMA-2-7B 为例（在常见基准上的相对变化）：

精度          模型大小    精度损失（vs FP16）
────────────────────────────────────────
FP16 (基准)    14 GB      0%
BF16           14 GB      ≈ 0%（训练更稳定）
INT8           7 GB       0.1-0.5%
INT4 (GPTQ)   3.5 GB     0.5-2%
INT4 (AWQ)    3.5 GB     0.3-1.5%
NF4 (QLoRA)   3.5 GB     1-3%
INT3          2.6 GB     2-5%（开始有感觉了）
INT2          1.75 GB    5-15%（通常不可接受）

关键发现：
  INT8 → 几乎无损
  INT4 → 有微小损失，大多数应用可接受
  INT3 → 开始有影响，某些任务还行
  INT2 → 通常太粗糙
```

### 哪些层最怕量化？

```
不是所有层对量化的敏感度一样：

最不敏感（可以用更低精度）：
  ✅ FFN（前馈网络）的中间层 → 参数最多，冗余最大
  ✅ Attention 的 V/O 投影矩阵 → 相对容忍
  ✅ 靠近输出的层 → 已经做了足够多的抽象

最敏感（要小心量化）：
  ⚠️ Embedding 层 → 直接影响所有后续计算
  ⚠️ Attention 的 Q/K 投影矩阵 → 对注意力分布敏感
  ⚠️ 模型的第一层和最后一层 → 输入输出的"门户"

这个发现催生了"混合精度量化"：
  敏感层用 INT8，不敏感层用 INT4
  → 平均精度不到 5-bit，但效果接近 INT8
```

## 🔑 关键洞察

1. **量化的本质是线性映射**：找到浮点范围到整数范围的缩放关系，scale 和 zero_point 是两个关键参数
2. **权重分布是量化的"朋友"**：神经网络权重集中在 0 附近（正态分布），使得低精度量化成为可能
3. **粒度很关键**：逐通道量化比逐张量量化的精度损失小很多，代价只是多存几 KB 的 scale
4. **PTQ 够用，QAT 更精**：大模型用训练后量化就够了，小模型或极致场景才需要量化感知训练
5. **INT4 是甜蜜点**：存储降低 4 倍，精度损失 1-3%，是当前 LLM 部署的主流选择
6. **不是所有层都一样**：Embedding 和 Q/K 投影对量化更敏感，FFN 最不敏感——混合精度量化利用了这个特性

---

## 📝 一句话总结

> 量化的核心思想：神经网络权重像正态分布的"小山丘"——大部分挤在 0 附近，只有少数" outliers "在远处。利用这个特性，线性映射把连续浮点数"塞进" 256（INT8）或 16（INT4）个格子里，存储降低 4-8 倍，精度只损失 1-3%。选择对称/非对称、逐张量/逐通道的粒度、PTQ/QAT 的策略，是工程实践中需要权衡的关键决策。

## 📖 关键术语速查

| 术语 | 含义 |
|------|------|
| **量化（Quantization）** | 把高精度数值映射到低精度整数，减少存储和计算开销 |
| **Scale** | 缩放因子，浮点范围与整数范围的比例 |
| **Zero Point** | 零点偏移，确保 0 能被精确表示 |
| **对称量化** | 零点为 0，范围关于原点对称的量化方式 |
| **非对称量化** | 零点不为 0，范围可以偏移的量化方式 |
| **逐张量量化** | 整个张量共享一组 scale/zero_point |
| **逐通道量化** | 每个输出通道有自己的 scale/zero_point |
| **逐组量化** | 每组固定大小的元素共享 scale/zero_point |
| **PTQ** | 训练后量化，不需要重新训练 |
| **QAT** | 量化感知训练，训练时模拟量化误差 |
| **校准数据（Calibration）** | PTQ 中用于统计激活值范围的少量样本 |
| **STE** | 直通估计器，让不可导的 round() 函数能反向传播 |
| **伪量化（Fake Quantization）** | 量化后立即反量化，用于 QAT 中模拟量化噪声 |
| **量化误差** | 量化前后数值的差异，量级约为 scale/2 |

> 🤔 **今天留下的悬念**：我们手写的线性量化器虽然能工作，但它对所有权重一视同仁——用同样的 scale 压缩整个通道。但现实中，某些权重比其他权重"重要得多"（比如决定注意力分配的关键权重），一刀切的量化可能会伤到它们。那有没有更"聪明"的量化方法？GPTQ、AWQ、GGUF 这些名字你一定见过——明天我们就来对比这些进阶量化方案，看它们怎么保护"重要权重"。
