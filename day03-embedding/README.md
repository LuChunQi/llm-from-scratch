# Day 3: 词嵌入（Word Embedding）— 让文字变成"坐标"

> 从 One-hot 到分布式表示，理解 Word2Vec 的核心思想

---

## 🤔 为什么需要词嵌入？

回忆一下前两天的内容：我们用 N-gram 统计词语出现的频率，用 BPE 把文本切成 token。但不管怎么切，计算机只能处理数字——所以问题来了：

**怎么把一个词变成数字？**

最直觉的方法就是 **One-hot 编码**。假设我们的词典有 5 个词：

```
猫 = [1, 0, 0, 0, 0]
狗 = [0, 1, 0, 0, 0]
鱼 = [0, 0, 1, 0, 0]
跑 = [0, 0, 0, 1, 0]
吃 = [0, 0, 0, 0, 1]
```

看起来很干净对吧？但问题大了：

### One-hot 的三大致命伤

1. **维度爆炸**：词典有 5 万个词，每个词就是 5 万维的向量。GPT-4 的词表约 10 万，那就是 10 万维！绝大多数位置都是 0，白白浪费空间。

2. **语义鸿沟**：在 One-hot 的世界里，"猫"和"狗"的距离 = "猫"和"跑"的距离。它们之间的**内积全是 0**（因为只有一个位置是 1，且位置不同）。这对计算机来说，所有词都是"一样不相关"的。

   打个比方：就像用身份证号来代表人——我的身份证尾号 3847 和你的 9251，数字之间没有任何关系，但我和你可能是好朋友。

3. **无法泛化**：模型学到了"猫吃鱼"的知识，但完全无法迁移到"狗吃肉"——因为在 One-hot 空间里，"猫"和"狗"没有任何关联。

**我们需要一种表示方法，让语义相近的词在数学上也相近。** 这就是词嵌入。

---

## 🌍 分布式假设：物以类聚，词以境分

1957 年，英国语言学家 J.R. Firth 说了一句名言：

> **"You shall know a word by the company it keeps."**
> （你可以通过一个词的邻居来认识它）

这就是 **分布式假设（Distributional Hypothesis）**：**出现在相似上下文中的词，往往有相似的意思。**

举个例子：
- "我今天去银行**存钱**" → "银行"和金融相关
- "我坐在河**岸**边看风景" → "岸"和地理相关

同样是 "bank"，因为周围的词不同，含义就不同。反过来说，"猫"和"狗"经常出现在相似的句子里（"我家养了一只___"、"___很可爱"），所以它们语义相近。

**词嵌入的核心思想就是：把词映射到一个低维连续空间（比如 100 维、300 维），让语义相近的词在这个空间里靠得更近。**

类比一下：
- One-hot 就像给每个中国人一个唯一的身份证号，号码之间毫无规律
- 词嵌入就像给每个人一个 GPS 坐标——住在同一片区的人坐标接近，代表他们有相似的"属性"

---

## 🧮 Word2Vec：把"邻居关系"变成数学

2013 年，Google 的 Tomas Mikolov 团队提出了 **Word2Vec**，它有两个变体：

### 1. CBOW（Continuous Bag of Words）
**用上下文预测中间词。**

好比考试填空："今天天气很___，我们出去玩吧"。你根据周围的词，猜出中间是"好"或"晴朗"。

```
输入：[今天, 天气, 很, 我们, 出去, 玩]（上下文）
目标：好（中心词）
```

### 2. Skip-gram
**用中心词预测上下文。**

反过来，给你一个词"好"，让你猜它周围可能出现哪些词。

```
输入：好（中心词）
目标：[今天, 天气, 很, 我们, 出去, 玩]（上下文）
```

**Skip-gram 更常用**，因为它的训练方式天然产生高质量的词向量。今天我们手写的就是 Skip-gram。

---

## 🏗️ Skip-gram 的架构（非常简单！）

别被图吓到，Skip-gram 的网络结构其实极其简单：

```
输入层（One-hot）  →  隐藏层（嵌入矩阵）  →  输出层（Softmax）
   V 维                V × D 维               V 维

V = 词表大小
D = 嵌入维度（超参数，通常 100~300）
```

### 前向传播过程

1. **输入**：中心词的 One-hot 向量 `x`（V 维，只有一个 1）
2. **隐藏层**：乘以权重矩阵 `W`（V × D），得到一个 D 维向量
   - 因为 x 是 one-hot，所以这一步等价于 **从 W 中取出第 i 行**
   - 这个 D 维向量就是当前词的**嵌入向量**
3. **输出层**：乘以权重矩阵 `W'`（D × V），得到 V 维 logits
4. **Softmax**：转成概率分布，预测每个词出现在上下文的概率

### 关键洞察

训练完成后，**权重矩阵 W 的每一行就是一个词的嵌入向量！**

这就像一个"查表"操作：矩阵 W 是一本字典，第 i 行就是第 i 个词的 D 维坐标。

---

## 📐 数学细节（简化版）

### 损失函数

给定中心词 `w_c` 和一个上下文词 `w_o`，我们要最大化：

```
P(w_o | w_c) = softmax(W' · (W · x_c))[w_o]
```

对于整个训练集，损失函数为（负对数似然）：

```
L = -Σ log P(w_o | w_c)  （对所有 (中心词, 上下文词) 对求和）
```

### Negative Sampling（负采样）

Softmax 的分母要对所有 V 个词求和，V 很大时计算量爆炸。

负采样的妙招：**不计算所有词的概率，而是随机抽几个"负样本"（不在上下文中的词），只优化这些词的概率。**

好比考试不考全部 1000 题，只随机抽 10 道来评估——虽然不完美，但效率高得多。

损失函数变成：

```
L = -log σ(u_o · v_c) - Σ log σ(-u_k · v_c)
     ↑ 正样本（真实的上下文词）  ↑ 负样本（随机抽的无关词）
```

其中 `σ` 是 sigmoid 函数，`v_c` 是中心词向量，`u_o` 是上下文词向量。

## 🎯 训练完成后我们能得到什么？

一个 **嵌入矩阵**，每一行是一个词的向量表示：

```
king   → [0.50, 0.68, -0.12, ...] 
queen  → [0.49, 0.71, -0.15, ...]
man    → [0.31, 0.43, -0.08, ...]
woman  → [0.30, 0.46, -0.11, ...]
apple  → [-0.20, 0.15, 0.80, ...]
```

最经典的现象是**词向量的算术运算**：

```
king - man + woman ≈ queen
Paris - France + China ≈ Beijing
walked - walk + swim ≈ swam
```

这不是魔法！因为向量空间学到了语义关系：
- `king - man` 提取了"皇室"这个维度
- 加上 `woman` 就得到了"女性皇室" → queen

就像在 GPS 坐标上：从"北京"往南移 1000 公里，大概就是"南京"的位置。

## 🔬 今天的代码做什么？

我们用 PyTorch 从零实现 Skip-gram Word2Vec：

1. **构造训练数据**：从文本中提取 (中心词, 上下文词) 对
2. **定义模型**：两个嵌入层（中心词矩阵 W 和上下文词矩阵 W'）
3. **实现负采样**：提高训练效率
4. **训练**：在小语料上跑几百轮
5. **可视化**：用 PCA 降到 2D，画出词向量的分布图

运行后你会看到：
- 训练损失逐步下降
- 相似的词（如 "king"/"queen"、"cat"/"dog"）在向量空间中聚在一起
- 词向量运算 king - man + woman ≈ queen 的效果

## 💡 词嵌入的历史地位

Word2Vec 虽然是 2013 年的"老古董"了，但它的思想影响深远：

1. **开创了"预训练"范式**：先在大规模语料上训练通用表示，再用于下游任务
2. **证明了分布式表示的威力**：低维向量比 one-hot 强太多
3. **直接影响了 Transformer**：BERT 的输入就是 WordPiece Embedding + 位置编码，本质上还是词嵌入的思想

但 Word2Vec 也有局限：
- **一词一义**："bank" 不管是银行还是河岸，都是同一个向量
- 后来 BERT 通过上下文化解决了这个问题（Day 5 之后会讲到）

---

## 📝 一句话总结

**词嵌入就是把词映射到低维向量空间，让语义相近的词在数学距离上也相近；Word2Vec 通过"预测上下文"这个任务自动学出这种表示。**
