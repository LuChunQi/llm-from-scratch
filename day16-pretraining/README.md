# Day 16: 预训练 — 让 Transformer 从零学会"说人话"

## 🔗 上节回顾

前 15 天我们一块一块拆解了 Transformer 的每个零件——Self-Attention、多头注意力、位置编码、FFN、LayerNorm、残差连接、Decoder-Only 架构、KV Cache、GQA、Flash Attention。每个零件我们都理解了：它是什么、为什么需要、怎么实现。

但零件终究是零件。你会造螺丝钉、会造齿轮、会造弹簧，不等于你会造一台发动机。

> **今天留下的悬念**：这些零件是怎么拼在一起变成一个完整模型的？从随机权重到能生成文本，训练过程中到底发生了什么？

今天我们进入第三模块——**训练与优化**。第一站就是最核心的：**预训练（Pretraining）**。我们用一个小数据集从头训练一个玩具级 GPT，亲眼见证 Transformer 从胡言乱语到学会"说人话"的整个过程。

---

## 🎭 从"鹦鹉学舌"说起：预训练到底是什么

> ❓ **问题**：让一个模型"学会说话"，最自然的方式是什么？

想象你要教一只鹦鹉说话。你怎么做？

不是给它一本语法书，不是给它一本词典，更不是给它讲"主谓宾"。你只是——**每天在它面前说话**。说很久很久。然后有一天，它突然开口了："你好！"

鹦鹉不懂语法，不懂语义。它做的事情极其简单：**听了足够多的话之后，学会了"下一个字应该说什么"**。

这就是预训练。

更准确地说：

```
预训练 = 让模型阅读海量文本，学习"给定前面的文字，预测下一个字"

输入："今天天气真"
目标：预测下一个字是 "好"（而不是 "差" 或 "吗"）

输入："The capital of France is"
目标：预测下一个词是 "Paris"
```

就这么简单。没有标签、没有人工标注、没有明确的"教"——只是让模型阅读，然后预测。

### 为什么这能学会"语言"？

因为**预测下一个词是一个极其苛刻的任务**。

要准确预测 "The capital of France is ___" 的下一个词，模型必须：
- 知道 "capital" 是什么意思（语义）
- 知道 "France" 是一个国家（世界知识）
- 知道国家对应首都（常识推理）
- 知道 "is" 后面应该跟名词（语法）

**表面上是预测下一个词，实际上逼迫模型学会了语法、语义、常识和推理。**

这就是所谓的"下一个词预测"（Next Token Prediction）任务，也叫"因果语言建模"（Causal Language Modeling）。

## 🏭 预训练的完整流水线

> ❓ **问题**：预训练不只是"喂数据"，具体要做哪些事？

预训练一条数据经过的完整路径：

```
原始文本                    Tokenizer                    模型                     损失
"今天天气真好"    →    [4521, 3892, 6721, 3409, 5567]    →    概率分布              →    计算损失
                            ↓                              ↓
                      切成输入/目标：                   每个位置预测下一个 token
                      输入: [4521, 3892, 6721, 3409]    P(token | 前面的 tokens)
                      目标: [3892, 6721, 3409, 5567]
```

让我们逐步拆解。

### 第 1 步：准备数据

语言模型需要大量的文本数据。真实预训练的数据量：

| 模型 | 训练数据量 | 来源 |
|------|-----------|------|
| GPT-2 | 40 GB 文本 | WebText（网页爬取） |
| GPT-3 | 570 GB 文本 | Common Crawl + 书籍 + 维基百科 |
| LLaMA | 1.4 TB 文本 | 多种公开数据混合 |

我们今天用 Shakespeare 的作品作为训练数据——只有约 1 MB，但足够让模型学会莎士比亚风格。

### 第 2 步：Tokenizer 编码

把文本转成 token ID 序列。今天我们用最简单的**字符级 Tokenizer**——每个字符就是一个 token。这样可以避免引入 BPE 的复杂性，让我们专注于训练过程本身。

```
"Hello" → [H, e, l, l, o] → [7, 4, 11, 11, 14]

词汇表大小 = 所有出现的唯一字符数
```

### 第 3 步：构造训练样本

语言模型的训练样本是 **(输入, 目标)** 对：

```
文本序列：[a, b, c, d, e, f, g, h, ...]
block_size = 4（上下文长度）

输入: [a, b, c, d]  →  目标: [b, c, d, e]
输入: [b, c, d, e]  →  目标: [c, d, e, f]
输入: [c, d, e, f]  →  目标: [d, e, f, g]
...
```

注意：**目标就是输入向左移一位**。位置 i 的输入预测位置 i+1 的 token。这在 Transformer 中用 Causal Mask 自然实现。

### 第 4 步：前向传播

模型对每个位置输出一个**概率分布**（对所有可能的 token）：

```
输入:  [a, b, c, d]
       ↓  ↓  ↓  ↓
模型:  P₁ P₂ P₃ P₄    每个位置输出 vocab_size 维的概率分布
       ↓  ↓  ↓  ↓
预测:  b  c  d  e     取概率最大的（或采样）
```

### 第 5 步：计算损失

用**交叉熵损失（Cross-Entropy Loss）**衡量预测和真实的差距：

```
Loss = -Σ log(P(target_token))

如果模型预测正确的下一个 token 概率 = 1.0，loss = 0
如果模型预测正确 token 概率 = 0.01，loss = 4.6（很大）
```

直觉：**损失 = "模型的惊讶程度"**。如果正确答案出人意料，模型就很惊讶，损失就高。训练的目标就是让模型对正确答案越来越不惊讶。

### 第 6 步：反向传播 + 更新权重

```
损失 → 计算梯度（每个参数的"调整方向"）→ 更新权重
```

重复数百万次，模型的预测越来越准确。

## 🧪 玩具级 GPT 的架构

> ❓ **问题**：我们之前学了 Transformer 的各个零件，它们是怎么拼在一起的？

把之前 15 天学过的零件拼起来：

```
Input Token IDs: [4, 7, 12, 3]
       ↓
Token Embedding:  每个 token → d_model 维向量
Position Embedding: 每个位置 → d_model 维向量
       ↓
x = Token Embedding + Position Embedding
       ↓
┌──────────────── Transformer Block ────────────────┐
│  x → LayerNorm → Self-Attention → + 残差 → y₁    │  ← Day 6, 7, 10, 11
│  y₁ → LayerNorm → FFN → + 残差 → y₂              │  ← Day 9, 10, 11
└───────────────────────────────────────────────────┘
       ↓ （重复 N 次）
       ↓
LayerNorm → Linear(vocab_size) → Softmax
       ↓
输出概率分布：每个位置预测下一个 token
```

每一行都是一个我们之前学过的零件！现在它们终于合体了。

### 我们的小 GPT 配置

```
vocab_size = 65      # Shakespeare 中所有唯一字符
d_model = 128        # 嵌入维度（GPT-3 是 12288）
n_heads = 4          # 注意力头数（GPT-3 是 96）
n_layers = 4         # Transformer Block 层数（GPT-3 是 96）
block_size = 64      # 上下文长度（GPT-3 是 2048）
dropout = 0.1        # Dropout 率
```

用 GPT-3 的标准来衡量，这是一个极其"迷你"的模型。但麻雀虽小，五脏俱全——架构完全一样，只是规模缩小了几千倍。

## 📉 训练循环：从损失曲线看"学习"

> ❓ **问题**：训练过程中发生了什么？怎么判断模型在"学习"？

训练循环的核心代码：

```python
for epoch in range(num_epochs):
    for x, y in dataloader:
        # 前向传播
        logits = model(x)              # (batch, seq_len, vocab_size)
        
        # 计算损失
        loss = cross_entropy(
            logits.view(-1, vocab_size),  # 展平：所有位置的预测
            y.view(-1)                     # 展平：所有位置的目标
        )
        
        # 反向传播
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
```

训练过程中，损失曲线会呈现这样的趋势：

```
Loss
│\
│ \                          
│  \                        
│   \___                    
│       \___                
│           \____           
│                \______    
│                     \_____
│                          \___________
└─────────────────────────────────────── Step
```

- **初始阶段**：损失很高，模型输出接近随机（因为权重是随机的）
- **快速下降**：模型学到了常见模式（常见词、常见组合）
- **缓慢下降**：模型学到了更复杂的模式（语法结构、长距离依赖）
- **收敛**：模型在训练数据上的损失趋于稳定

## 🎨 从训练过程看"涌现"

> ❓ **问题**：模型是"突然"学会说话的，还是"慢慢"学会的？

一个迷人的观察：模型的能力是**分阶段涌现**的。

```
Step 0:    随机输出      "xT5m w2p q9f..."
Step 500:  学会了字母频率  "e t a o i n s h r d..."
Step 2000: 学会了单词      "the and to of a in..."
Step 5000: 学会了短语      "the king and the..."
Step 10000: 学会了句子结构  "To be, or not to..."
```

这就像婴儿学说话：
1. 先学会发元音
2. 再学会发辅音
3. 然后学会说单词
4. 最后学会说句子

**模型先学会数据中的统计规律（哪些字母最常见），再学会结构规律（字母怎么组成单词），最后学会语义规律（单词怎么组成句子）。**

## ⚙️ 关键训练技巧

> ❓ **问题**：除了"喂数据 + 梯度下降"，还有什么技巧能让训练更稳？

### 学习率预热（Warmup）

```
学习率
│          ┌──────────────────
│         /
│        /
│       /
│      /
│     /
│    /
│___/
└────────────────────────── Step
   预热期    正常训练期
```

训练刚开始时，模型参数是随机的，梯度方向不稳定。如果学习率太大，参数会剧烈震荡。所以先从小学习率开始，慢慢增大（"热身"），等梯度稳定后再保持正常学习率。

### 梯度裁剪（Gradient Clipping）

```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
```

有时候某些参数的梯度会突然变得很大（"梯度爆炸"），导致参数更新太猛。梯度裁剪把梯度的范数限制在一个阈值内，防止这种情况。

### 学习率余弦衰减（Cosine Decay）

```
学习率
│\.
│  \
│   \
│    \.
│      \.
│        \.
│          \...._____
│                 ____
└────────────────────────── Step
```

训练后期，学习率逐渐衰减到接近 0，让模型参数在最优值附近精细调整，而不是大幅震荡。

## 📊 和真实预训练的差距

> ❓ **问题**：我们的玩具实验和 GPT-4 的预训练差多远？

| 维度 | 我们的玩具 GPT | GPT-3 | GPT-4（估计） |
|------|-------------|-------|-------------|
| 参数量 | ~1M | 175B | ~1.8T |
| 训练数据 | 1 MB | 570 GB | ~10 TB |
| 训练成本 | 免费（CPU 几分钟） | ~$4.6M | ~$100M+ |
| 训练硬件 | CPU | V100 集群 | H100 超级集群 |
| 上下文长度 | 64 | 2048 | 128K+ |
| 输出质量 | 像莎士比亚 | 像人类 | 超越人类 |

差距是几万倍到几十万倍。但**核心原理完全一样**——下一个词预测 + Transformer + 梯度下降。真实预训练只是"做同样的事，但规模大了几万倍"。

## 🔑 预训练教会了我们什么

1. **预训练的本质就是"下一个词预测"**——通过大量阅读，学会语言的统计规律
2. **架构 = 我们学过的所有零件拼在一起**——Embedding + Attention + FFN + LayerNorm + 残差
3. **损失 = 模型的"惊讶程度"**——训练目标就是让正确答案不再令人惊讶
4. **能力是涌现的**——先学统计、再学结构、最后学语义
5. **和真实 LLM 的差距在于规模，不在于原理**——同样的方法，放大数据和模型就能得到 GPT-4

## 🔑 关键洞察

1. **预训练 = 下一个词预测**——通过大量阅读学会语言
2. **Transformer 是预训练的标准架构**——所有零件终于合体了
3. **训练循环 = 前向 + 损失 + 反向 + 更新**——就这么简单
4. **能力涌现是分阶段的**——统计 → 结构 → 语义
5. **规模是唯一真正的差距**——原理相同，只是数据量和计算量大了几个数量级
6. **预训练模型学到的只是"语言的统计规律"**——它不会按指令回答问题，那需要下一步 SFT

## 📝 一句话总结

> 预训练就是让 Transformer 阅读海量文本做"下一个词预测"——表面上是填空题，实际上逼迫模型学会了语法、语义和常识；架构就是我们前 15 天学的所有零件拼在一起，训练循环就是"前向 → 损失 → 反向 → 更新"四步循环往复。

## 📖 关键术语速查

| 术语 | 含义 |
|------|------|
| **预训练（Pretraining）** | 在大量无标注文本上训练语言模型，目标是下一个词预测 |
| **下一个词预测（Next Token Prediction）** | 给定前面的 token，预测下一个 token 的任务 |
| **因果语言建模（Causal LM）** | 只看左边上下文预测下一个词（区别于 MLM） |
| **交叉熵损失（Cross-Entropy Loss）** | 衡量预测概率分布和真实分布的差距 |
| **涌现（Emergence）** | 模型能力随训练/规模增长分阶段出现 |
| **学习率预热（Warmup）** | 训练初期从小学习率慢慢增大，让训练更稳定 |
| **梯度裁剪（Gradient Clipping）** | 限制梯度大小，防止梯度爆炸 |
| **余弦衰减（Cosine Decay）** | 学习率按余弦曲线衰减，训练后期精细调整 |
| **困惑度（Perplexity）** | 模型"困惑程度"的度量，等于 exp(loss)，越低越好 |
