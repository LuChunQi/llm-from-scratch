# Day 7: Multi-Head Attention — 为什么一个头不够用？

## 🎯 今天的目标

昨天我们搞懂了 Self-Attention：一个词通过 Q/K/V 三矩阵去"关注"句子中的其他词。但问题是——**只用一个注意力头，就像只用一只眼睛看世界**。

Multi-Head Attention（多头注意力）就是给 Transformer 戴上一副"昆虫复眼"——多个头同时看，每个头关注不同的东西，最后拼起来得到更完整的理解。

读完本文，你会：
1. 明白为什么单头注意力不够
2. 搞懂多头注意力的数学原理
3. 理解不同头"看到了什么"
4. 手写一个完整的 Multi-Head Attention，并可视化每个头的关注模式

---

## 1. 回顾：单头注意力的局限

昨天我们写了：

```
Attention(Q, K, V) = softmax(QK^T / √d_k) · V
```

假设 d_model = 512，一个头的 d_k = 512。这意味着**所有信息被压缩到一个 512 维的空间里**。

### 类比时间 🎯

想象你在读一句话："**苹果**公司昨天发布了一款新手机，不过我觉得**苹果**还是水果好吃。"

一个注意力头可能只会学到一种关注模式：
- 也许它学到"关注语法关系"（动词关注主语）
- 也许它学到"关注语义相似性"（两个"苹果"互相关注）

**但它很难同时学到所有这些模式。** 就像你用一把扳手修所有东西——有些螺丝拧得上，有些拧不上。

---

## 2. 多头注意力的核心思想

### 2.1 "分头行动"策略

Multi-Head Attention 的做法非常直觉：

1. **把 Q、K、V 分别投影到 h 个不同的子空间**
2. **每个头独立做 Attention**
3. **把所有头的结果拼接起来**
4. **再做一次线性投影，融合所有头的信息**

用公式表示：

```
MultiHead(Q, K, V) = Concat(head_1, head_2, ..., head_h) · W_O

其中：
head_i = Attention(Q · W_Q_i, K · W_K_i, V · W_V_i)
```

### 2.2 类比：编辑部的故事 📰

把 Transformer 想象成一个编辑部，在分析一篇文章：

| 头 | 角色 | 关注什么 |
|---|---|---|
| head_1 | 语法审查员 | 主谓宾关系、词性搭配 |
| head_2 | 语义分析员 | 词义的相似性和关联 |
| head_3 | 指代消解员 | "他"指代谁、"这个"指什么 |
| head_4 | 位置感知员 | 句首/句尾/相邻关系 |
| head_5 | 情感分析员 | 正面/负面情感词 |
| ... | ... | ... |
| head_8 | 长距离关联 | 句首和句尾的呼应 |

每个头独立工作，各司其职。最后主编（W_O 矩阵）把所有报告汇总，做出最终判断。

**关键洞察：这些分工不是人工设定的，而是模型在训练中自动学出来的！** Transformer 不需要你告诉它"头1去看语法"——训练数据会自动教会每个头该关注什么。

## 3. 数学细节：维度怎么切？

这是很多人困惑的地方。我们用一个具体例子来算：

假设：
- d_model = 512（模型总维度）
- h = 8（8 个头）
- d_k = d_v = d_model / h = 64（每个头的维度）

### 3.1 输入投影

```
# 输入 X: [batch, seq_len, d_model] = [batch, seq_len, 512]

# 每个头有自己的 W_Q, W_K, W_V:
W_Q_i: [512, 64]   # 投影到 64 维
W_K_i: [512, 64]
W_V_i: [512, 64]

# 总共 8 个头，所以总参数量：
# 8 × 3 × (512 × 64) = 786,432 参数
```

### 3.2 各头独立计算

```
# 头 i 的计算：
Q_i = X @ W_Q_i    # [batch, seq_len, 64]
K_i = X @ W_K_i    # [batch, seq_len, 64]
V_i = X @ W_V_i    # [batch, seq_len, 64]

scores_i = Q_i @ K_i^T / √64   # [batch, seq_len, seq_len]
attn_i = softmax(scores_i)      # [batch, seq_len, seq_len]
head_i = attn_i @ V_i           # [batch, seq_len, 64]
```

### 3.3 拼接 + 输出投影

```
# 拼接所有头：
concat = [head_1, head_2, ..., head_8]  # [batch, seq_len, 8×64] = [batch, seq_len, 512]

# 输出投影：
output = concat @ W_O    # W_O: [512, 512], 输出: [batch, seq_len, 512]
```

### 3.4 一个有趣的等价关系

注意看：拼接后 [batch, seq_len, 512] 再乘 W_O [512, 512]，和直接做一次大的 Attention 有什么区别？

**区别在于中间的 softmax！** 单头是在整个 512 维空间做 softmax，而多头是在每个 64 维子空间独立做 softmax。这让不同头可以独立地"分配注意力"，互不干扰。

## 4. 高效实现：用矩阵一次搞定所有头

实际代码中不会写循环处理每个头。我们把所有头的 W_Q/W_K/W_V 拼成一个大矩阵：

```python
# 所有头的投影矩阵合在一起：
W_Q: [512, 512]  # 一次性投影出 8 个头的 Q
W_K: [512, 512]
W_V: [512, 512]

# 投影后 reshape：
Q = X @ W_Q                        # [batch, seq_len, 512]
Q = Q.view(batch, seq_len, 8, 64)  # [batch, seq_len, 8, 64]
Q = Q.transpose(1, 2)              # [batch, 8, seq_len, 64]

# 现在 8 个头可以并行计算！
scores = Q @ K.transpose(-2, -1) / √64  # [batch, 8, seq_len, seq_len]
```

这就是 PyTorch 里 `nn.MultiheadAttention` 的实现方式。

## 5. 可视化：不同头真的在看不同的东西吗？

这是最酷的部分！研究表明，训练好的 Transformer 里，不同的头确实学到了不同的关注模式：

### 5.1 典型的注意力模式

```
句子："The cat sat on the mat because it was tired"

头 1 的注意力（it → 其他词）:
  The:  0.05
  cat:  0.72  ████████████████████  ← 关注"猫"
  sat:  0.03
  on:   0.02
  the:  0.01
  mat:  0.08
  because: 0.02
  it:   0.05
  was:  0.01
  tired: 0.01

头 3 的注意力（it → 其他词）:
  The:  0.02
  cat:  0.15
  sat:  0.05
  on:   0.03
  the:  0.02
  mat:  0.58  ████████████████  ← 关注"垫子"
  because: 0.03
  it:   0.04
  was:  0.03
  tired: 0.05
```

可以看到，头 1 认为 "it" 指代 "cat"，头 3 认为 "it" 指代 "mat"。**两个头各有道理，最终由 W_O 综合决定。**

### 5.2 注意力头的常见模式类型

| 模式 | 描述 | 示例 |
|------|------|------|
| **对角线** | 每个词主要关注自己 | 名词自关注 |
| **前一个** | 关注前一个词 | 捕捉局部序列 |
| **[CLS]关注** | 所有词关注特殊 token | 分类任务 |
| **分隔符关注** | 关注句号/逗号 | 句子边界感知 |
| **长距离** | 跳过多个词关注远处的词 | 指代消解 |

## 6. 为什么是 8 个头？头数怎么选？

### 6.1 头数 vs 维度的权衡

常见的配置：

| 模型 | d_model | 头数 h | d_k |
|------|---------|--------|-----|
| BERT-Base | 768 | 12 | 64 |
| BERT-Large | 1024 | 16 | 64 |
| GPT-2 | 768 | 12 | 64 |
| GPT-3 (175B) | 12288 | 96 | 128 |
| LLaMA-7B | 4096 | 32 | 128 |
| LLaMA-70B | 8192 | 64 | 128 |

**规律：d_k 通常在 64-128 之间。** 太小了信息不够，太大了头数少、多样性不够。

### 6.2 计算量对比

```
单头注意力：O(n² · d_model)

多头注意力：O(h · n² · d_k) = O(h · n² · d_model/h) = O(n² · d_model)
```

**惊喜：多头注意力的计算量和单头一样！** 但效果显著更好。这就是多头设计的精妙之处——不增加计算量，但增加了模型的表达能力。

## 8. 常见问题

### Q: 多头注意力和卷积有什么相似之处？

A: 很好的类比！
- **CNN 的多个 filter**：每个 filter 学不同的特征（边缘、纹理、颜色）
- **Transformer 的多个 head**：每个 head 学不同的注意力模式（语法、语义、位置）

两者都是"多视角"的设计哲学。

### Q: 可以用不同大小的头吗？

A: 理论上可以，但实践中几乎没人这么干。原因是：统一大小方便并行计算，而且目前没有明确证据不等大的头效果更好。

### Q: 头数越多越好吗？

A: 不是。研究表明头数存在"甜点"：
- 太少了：模型表达能力不足
- 太多了：每个头的维度太小（d_k 过小），信息不够
- 而且，过多头可能有冗余（某些头学到相似的模式）

---

## 📝 一句话总结

**Multi-Head Attention 把注意力空间切成多个子空间，让不同的"眼睛"同时关注不同方面，是 Transformer 强大表达力的关键来源——而且不增加计算量。**

## 🔑 关键术语速查

| 术语 | 含义 |
|------|------|
| **Multi-Head Attention** | 多头注意力，多个独立的注意力头并行工作 |
| **d_model** | 模型的隐藏维度（如 512、768） |
| **d_k / d_v** | 每个头的查询/值维度，等于 d_model / h |
| **h (num_heads)** | 注意力头的数量 |
| **W_O (output projection)** | 输出投影矩阵，将所有头的拼接结果映射回 d_model |
| **head diversity** | 头多样性，不同头关注不同模式的现象 |
| **attention pattern** | 注意力模式，描述一个头如何分配注意力权重 |
