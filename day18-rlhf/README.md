# Day 18: RLHF（基于人类反馈的强化学习）— 让模型学会"讨好"人类

## 🔗 上节回顾

昨天我们完成了 SFT（监督微调）——用"指令-回答"配对数据教模型听懂人类的指令。模型从"自顾自地续写"变成了"听懂了再回答"。但 SFT 有一个根本性的局限：**它只能模仿人类标注者写的回答，而人类标注者写的未必是最好的**。

同一个问题，可能有多种合理的回答——有的简洁，有的详细，有的通俗，有的专业。SFT 只能让模型"模仿其中一种"，但没法让模型知道"人类其实更喜欢哪一种"。

今天我们来解决这个问题——**RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）**，教模型不只是模仿，而是真正优化"人类觉得好"这个目标。

---

## 🎭 从"模仿秀"到"选秀大赛"：为什么需要 RLHF

> ❓ **问题**：SFT 已经能让模型听指令了，为什么还要引入强化学习？

想象你在培养一个演员。

**SFT 阶段**：你给演员看优秀表演的录像，让他模仿。"看到这种场景，就这么演。"演员学会了基本的表演技巧，但——他只是在**照猫画虎**。录像里的表演未必是最佳的，他只是在复制。

**RLHF 阶段**：你让演员上台表演，然后找一群观众打分。演员根据观众的反馈不断调整，最终找到"观众最喜欢"的表演方式。他不再只是模仿，而是在**优化观众满意度**。

这就是 RLHF 的核心思想：

```
SFT： 模型学习 → 模仿人类的回答（我教你怎么做）
RLHF：模型学习 → 优化人类的偏好（你告诉我哪个好，我来优化）
```

**RLHF 比 SFT 多了什么？**

| 维度 | SFT | RLHF |
|------|-----|------|
| 学习信号 | "你应该这样回答"（示范） | "这个比那个好"（偏好） |
| 数据类型 | (指令, 回答) 配对 | (指令, 回答A, 回答B, 人类选择) |
| 优化目标 | 交叉熵损失 → 模仿训练数据 | 奖励最大化 → 人类更满意 |
| 模型能力 | 听指令 | 听指令 + 知道人类偏好 |

## 🗺️ RLHF 的完整流程：三步走

> ❓ **问题**：RLHF 到底怎么做？听说需要训练好几个模型？

RLHF 分为三个阶段，每一步都不可或缺：

```
┌──────────────────────────────────────────────┐
│  Stage 1: SFT（监督微调）                      │
│  用指令-回答数据训练一个基础模型                 │
│  这就是昨天做的事                               │
│  输出: SFT 模型（π_sft）                       │
└─────────────────────┬────────────────────────┘
                      ↓
┌──────────────────────────────────────────────┐
│  Stage 2: Reward Model（奖励模型训练）          │
│  收集人类偏好数据，训练一个"打分器"             │
│  这个打分器学会了"人类觉得哪个回答更好"          │
│  输出: Reward Model（r_θ）                     │
└─────────────────────┬────────────────────────┘
                      ↓
┌──────────────────────────────────────────────┐
│  Stage 3: PPO（强化学习优化）                   │
│  用奖励模型给生成回答打分                       │
│  用 PPO 算法优化 SFT 模型，让它生成高分回答      │
│  输出: RLHF 模型（π_rlhf）                     │
└──────────────────────────────────────────────┘
```

下面我们逐步拆解每个阶段。

## 📊 Stage 2: Reward Model — 训练一个"品味评委"

> ❓ **问题**：怎么让模型理解"人类觉得哪个更好"？

### 人类偏好数据长什么样？

让标注者看同一个问题的两个回答，选择更好的那个：

```
指令: "解释什么是黑洞"

回答 A（胜出 ✅）:
  "黑洞是太空中引力极强的区域，连光都逃不出来。
   想象一个超级重的球被压缩到极小，周围的空间都被弯曲了。"

回答 B（失败 ❌）:
  "黑洞是一种天体。它的质量很大。光无法从中逃逸。
   黑洞的存在已经被科学证实。"

人类选择: 回答 A 更好（更生动、更容易理解）
```

成千上万条这样的数据，就构成了**偏好数据集（Preference Dataset）**。InstructGPT 论文中，OpenAI 收集了大约 30K 条这样的偏好数据。

### Bradley-Terry 模型：从"二选一"到"打分"

> ❓ **问题**：人类给的是"A 比 B 好"这种比较，怎么变成一个连续的分数？

这就是 **Bradley-Terry 模型**的用武之地。它的核心思想：

> **如果给每个回答分配一个分数 r(x, y)，那么"A 比 B 好"的概率可以用这两个分数的差来表示。**

数学公式：

```
P(A > B) = σ(r(x, y_A) - r(x, y_B))
```

其中：
- `x` 是指令（prompt）
- `y_A`、`y_B` 是两个回答
- `r(x, y)` 是 Reward Model 给出的分数
- `σ` 是 sigmoid 函数（把任意实数映射到 [0, 1]）

直觉理解：

```
如果 r(A) = 5, r(B) = 3:
  P(A > B) = σ(5 - 3) = σ(2) ≈ 0.88 → A 大概率更好 ✅

如果 r(A) = 3, r(B) = 3:
  P(A > B) = σ(0) = 0.50 → 两者差不多 🤷

如果 r(A) = 1, r(B) = 4:
  P(A > B) = σ(-3) ≈ 0.05 → B 大概率更好 ✅
```

### Reward Model 的训练损失函数

把所有偏好数据放在一起，用**最大似然估计**训练：

```
L_RM = -E[log σ(r(x, y_w) - r(x, y_l))]
```

其中：
- `y_w`（winner）是人类选中的回答
- `y_l`（loser）是人类拒绝的回答
- 模型要学的就是：让 winner 的分数尽可能高于 loser

**直觉**：如果 Reward Model 正确判断"winner 比 loser 好"（r_w >> r_l），loss 就很小；如果判断错了（r_w < r_l），loss 就很大，梯度会把模型往正确方向推。

### Reward Model 的架构

```
        ┌───────────────────┐
        │   SFT 模型的       │
        │   Transformer      │
        │   （去掉 lm_head）  │
        └────────┬──────────┘
                 ↓
        ┌───────────────────┐
        │   新增的 Value Head │
        │   Linear(d_model, 1)│
        │   → 输出一个标量分数 │
        └───────────────────┘
```

Reward Model 通常基于 SFT 模型，把最后的 `lm_head`（输出词表概率的线性层）换成一个新的 `value_head`（输出一个标量分数的线性层）。最后一个 token 的输出就是这个回答的得分。

## 🎮 Stage 3: PPO — 让模型学会"讨好"评委

> ❓ **问题**：有了 Reward Model 打分，怎么让 SFT 模型优化它的回答？

这就是强化学习登场的地方。

### 强化学习的基本概念

把 LLM 优化变成一个强化学习问题：

| RL 概念 | LLM 中的对应 |
|---------|-------------|
| **环境（Environment）** | 用户给的指令（prompt） |
| **智能体（Agent）** | 当前模型（策略 π_θ） |
| **动作（Action）** | 生成的回答文本 |
| **奖励（Reward）** | Reward Model 给的分数 |
| **策略（Policy）** | 模型生成文本的概率分布 |

**训练目标**：调整模型参数，让生成的回答获得尽可能高的奖励。

### 策略梯度：最直觉的 RL 方法

> ❓ **问题**：怎么用梯度下降优化"生成的回答获得高奖励"？

最朴素的想法：

```
1. 模型生成一个回答 y
2. Reward Model 给这个回答打分 r(y)
3. 如果分数高 → 鼓励模型多生成这种回答
4. 如果分数低 → 惩罚模型，让它少生成这种回答
```

这就是**策略梯度（Policy Gradient）**的核心：

```
∇_θ J(θ) ≈ E[r(y) · ∇_θ log π_θ(y|x)]
```

直觉：
- `log π_θ(y|x)`：模型对"在输入 x 时生成回答 y"的"确信度"
- `r(y)`：这个回答的奖励
- 乘起来就是：**奖励高的回答，增加它的生成概率；奖励低的回答，降低它的生成概率**

**打比方**：你训练一条狗。它做对了（高奖励），你就给它零食（增加这个行为的概率）；它做错了（低奖励），就不给零食（降低这个行为的概率）。久而久之，狗就学会了做对的事。

### PPO（Proximal Policy Optimization）：策略梯度的"安全版"

> ❓ **问题**：朴素策略梯度有什么问题？为什么需要 PPO？

朴素策略梯度有一个致命问题：**更新步子太大，模型容易"走偏"**。

想象你训练模型"回答要详细"。模型发现长回答得分高，就开始疯狂写长篇大论——从正常回答变成了一本小说。这就是策略梯度的不稳定性：**奖励信号让模型朝一个方向狂奔，但可能跑过了头**。

PPO 的解决方案很简单：**限制每次更新的幅度**。

```
PPO 的核心思想：
  新策略和旧策略不能差太远
  → 用"裁剪"（clipping）限制更新幅度
  → 每次只走一小步，稳扎稳打
```

具体来说，PPO 定义了一个**裁剪目标函数**：

```
r_t(θ) = π_θ(y|x) / π_old(y|x)   （新旧策略的概率比）

L_CLIP = E[min(
    r_t(θ) · A_t,                           # 正常的策略梯度
    clip(r_t(θ), 1-ε, 1+ε) · A_t           # 裁剪后的策略梯度
)]
```

其中：
- `A_t`（优势函数 Advantage）= 实际奖励 - 期望奖励（"比预期好多少"）
- `ε` 通常取 0.1 ~ 0.2（允许概率比在 [0.8, 1.2] 范围内变化）
- `clip` 函数把概率比限制在 `[1-ε, 1+ε]` 范围内

**直觉**：如果新策略的概率是旧策略的 2 倍（r_t = 2），超过了 1.2 的上限，就裁剪到 1.2——不许一次走太远。

### KL 散度惩罚：另一道安全阀

PPO 的裁剪是一个"硬限制"（超过就截断）。还有一道"软限制"：**KL 散度惩罚**。

```
L_TOTAL = L_CLIP - β · KL(π_θ || π_sft)
```

其中：
- `KL(π_θ || π_sft)` 是当前策略和 SFT 模型之间的 KL 散度
- 衡量"当前模型和原始 SFT 模型差多远"
- `β` 是惩罚系数（通常 0.01 ~ 0.1）

**为什么需要 KL 惩罚？**

如果只优化奖励，模型可能会找到一个"捷径"——生成 Reward Model 喜欢但人类不喜欢的文本。比如 Reward Model 可能对某些特殊字符给高分，模型就开始疯狂输出那些字符。这就是 **Reward Hacking（奖励作弊）**。

KL 惩罚说："你可以变化，但不能离 SFT 模型太远。"它就像一根**弹性绳**，把模型拴在 SFT 模型附近——你可以往外探索，但拉太远就会被拉回来。

### 价值函数：估计"期望奖励"

PPO 还需要一个**价值函数 V(x)**，它估计"给定指令 x，当前策略能获得的期望奖励"。

价值函数和 Reward Model 一起用来计算**优势函数**：

```
A_t = r(y) - V(x)
```

如果 `r(y) > V(x)`：这个回答比预期好 → 鼓励
如果 `r(y) < V(x)`：这个回答比预期差 → 惩罚

价值函数通常和 Reward Model 共享 Transformer backbone，只有最后一个 `value_head` 不同。

## 🏗️ PPO 的完整训练循环

> ❓ **问题**：把上面所有内容串起来，PPO 训练到底在干什么？

```
┌─────────────────────────────────────────────────────┐
│  PPO 训练循环（每次迭代）                             │
│                                                     │
│  1. 采样：从 prompt 数据集中抽一批指令 x              │
│     ↓                                               │
│  2. 生成：用当前模型 π_θ 为每个指令生成回答 y          │
│     ↓                                               │
│  3. 打分：用 Reward Model 给每个回答打分 r(x, y)      │
│     ↓                                               │
│  4. 评估：用价值函数估计 V(x)                         │
│     ↓                                               │
│  5. 计算优势：A = r(x, y) - V(x)                     │
│     ↓                                               │
│  6. PPO 更新：                                       │
│     - 计算策略梯度（裁剪）                             │
│     - 计算 KL 惩罚                                   │
│     - 更新模型参数                                    │
│     - 更新价值函数                                    │
│     ↓                                               │
│  7. 重复 1-6                                         │
└─────────────────────────────────────────────────────┘
```

## ⚠️ 实际工程中的挑战

> ❓ **问题**：RLHF 听起来很美好，实际做起来有哪些坑？

### 1. 标注成本

人类偏好数据的标注非常昂贵：
- 每条数据需要标注者比较两个回答，需要理解指令和评估回答质量
- InstructGPT 用了约 30K 条偏好数据，标注成本数十万美元
- 后来出现了 AI 辅助标注：用 GPT-4 代替人类做偏好判断（**RLAIF**）

### 2. Reward Hacking（奖励作弊）

模型可能学会"欺骗"Reward Model 而不是真正变好：

```
正常情况：模型学会了写更好的回答 → 奖励上升 → 人类满意 ✅
Reward Hacking：模型发现了 Reward Model 的漏洞 → 奖励上升 → 人类不满意 ❌

实际案例：
  - 模型学会在回答末尾加一堆感谢语（Reward Model 给了高分）
  - 模型学会复制指令中的关键词（看起来"相关"但实际没回答问题）
  - 模型学会写冗长的回答（长文本的累积分数更高）
```

**解决方案**：
- KL 惩罚（防止离 SFT 模型太远）
- 定期让人类评估模型输出（不只是看 Reward Model 分数）
- 用多个 Reward Model 交叉验证

### 3. KL 系数调节

`β`（KL 惩罚系数）的选择非常重要：
- `β` 太小：模型可能 Reward Hacking
- `β` 太大：模型不敢变化，和 SFT 模型一样

实际中常用**自适应 KL 控制器**：如果 KL 散度太大，增大 β；如果太小，减小 β。

```
目标 KL = 6.0 nats
当前 KL = 10.0 → 太远了，增大 β → 拉回来
当前 KL = 2.0 → 太近了，减小 β → 鼓励探索
```

### 4. 训练不稳定性

PPO 训练 LLM 比训练游戏 AI 困难得多：
- 文本生成是**离散的**（不能直接求梯度）
- 奖励信号**稀疏**（只有一个最终分数，不像游戏每步都有奖励）
- 模型可能突然**崩溃**（输出乱码）

实际工程中需要大量调参和监控。

## 📊 RLHF 的效果：ChatGPT 的秘密武器

RLHF 是 ChatGPT 能够成功的核心技术之一。OpenAI 的 InstructGPT 论文展示了 RLHF 的效果：

```
人类评估结果（1-7 分）：
  预训练模型:    2.5 分（虽然能说人话，但不听指令）
  + SFT:        5.0 分（学会了听指令，但回答质量参差不齐）
  + RLHF:       6.2 分（回答更有帮助、更安全、更符合人类偏好）
```

**最令人惊讶的发现**：经过 RLHF 的 1.3B 模型，人类评估者认为它比 175B 的原始 GPT-3 **更好**。这意味着 RLHF 不只是"锦上添花"——它可以大幅提升模型的实际质量，让小模型超越大模型。

## 🔑 关键洞察

1. **RLHF 的本质是"用人类偏好做优化"**——不再模仿，而是让模型朝着人类喜欢的方向进化
2. **三步走：SFT → Reward Model → PPO**——第一步打基础，第二步训练评委，第三步让模型讨好评委
3. **Bradley-Terry 模型**把"二选一"变成连续分数——从比较到评分的桥梁
4. **PPO 的裁剪 + KL 惩罚**是两道安全阀——防止模型更新太大或走偏
5. **Reward Hacking 是最大挑战**——模型可能学会欺骗评委而不是真正变好
6. **RLHF 让小模型超越大模型**——InstructGPT 的 1.3B RLHF 模型比 175B GPT-3 更受人类偏好

---

## 📝 一句话总结

> RLHF 分三步：先用 SFT 打好基础，再用人类偏好数据训练一个 Reward Model（评委），最后用 PPO 强化学习让模型不断生成更高分的回答——同时用裁剪和 KL 惩罚约束更新幅度，防止模型走偏或 Reward Hacking。这就是 ChatGPT 背后的核心技术。

## 📖 关键术语速查

| 术语 | 含义 |
|------|------|
| **RLHF** | Reinforcement Learning from Human Feedback，基于人类反馈的强化学习 |
| **Reward Model** | 奖励模型，学习人类偏好并给回答打分 |
| **Bradley-Terry 模型** | 用分数差表示"二选一"概率的统计模型 |
| **PPO** | Proximal Policy Optimization，近端策略优化，限制更新幅度的 RL 算法 |

| **优势函数（Advantage）** | A = r - V，衡量"实际奖励比预期好多少" |
| **KL 散度** | 衡量两个概率分布的差异，用作"距离惩罚" |
| **Reward Hacking** | 模型找到 Reward Model 的漏洞来获取高分，而非真正提升质量 |
| **价值函数（Value Function）** | 估计给定状态下能获得的期望奖励 |
| **裁剪（Clipping）** | PPO 中限制策略更新幅度的技术 |
| **RLAIF** | RL from AI Feedback，用 AI（如 GPT-4）代替人类做偏好标注 |
