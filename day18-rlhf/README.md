# Day 18: RLHF（基于人类反馈的强化学习）— 教模型"讨好"人类

## 🔗 上节回顾

昨天我们实现了 SFT（监督微调），让模型从"自顾自地续写"进化到"听懂指令再回答"。核心思路是：用"指令-回答"配对数据做监督训练，通过 Chat Template 区分角色、损失掩码只训练回答部分。但我们也留下了一个关键问题——**SFT 只教会了模型模仿人类标注者写的回答，而人类标注者写的未必是最好的**。同样的指令可能有多种合理的回答，SFT 没法学会"哪种回答人类更喜欢"。

今天我们就来解决这个问题——**RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）**，教模型不只是模仿，而是真正优化"人类觉得好"这个目标。

---

## 🎯 为什么 SFT 不够用？

> ❓ **问题**：SFT 已经教会了模型听指令，为什么还需要 RLHF？

SFT 的本质是**模仿学习**（Imitation Learning）。就像学开车——SFT 相当于坐在教练旁边，照着教练的动作一步步学。你能学会基本操作，但教练的习惯不一定是最优解。

具体到 LLM，SFT 有三个根本缺陷：

### 缺陷一：回答质量的天花板 = 标注者水平

```
指令: "解释量子纠缠"

SFT 训练数据（标注者写的）:
  "量子纠缠就是两个粒子之间有神秘的联系……"
  → 模型学到的是这个"还行但不精确"的回答

理论上更好的回答:
  "量子纠缠是两个量子系统之间的一种非经典关联。
   当两个粒子纠缠后，测量其中一个会瞬间确定另一个的状态，
   无论它们相距多远。这不是信息传递，而是量子态的关联性。"
```

模型的上限被标注者的水平锁死了。

### 缺陷二：无法区分"好"和"更好"

```
指令: "用一句话介绍太阳系"

回答 A: "太阳系是以太阳为中心的行星系统，包含八大行星。"
回答 B: "太阳系是一个由太阳、八大行星、矮行星、小行星和彗星等天体
         组成的引力束缚系统，位于银河系猎户臂中。"
```

两个回答都正确，但 B 更好。SFT 训练时只见过一种回答，没法学会这种"谁更好"的偏好。

### 缺陷三：无法优化复杂目标

一个好的助手回答应该满足很多标准：
- **有用（Helpful）**：回答解决了用户的问题
- **诚实（Honest）**：回答是事实正确的
- **无害（Harmless）**：回答不会造成伤害
- **简洁**：不啰嗦
- **礼貌**：语气得体

SFT 的损失函数是"预测下一个词的交叉熵"——它只优化"和训练数据像不像"，完全不关心这些质量标准。

**RLHF 的目标就是打破这些天花板，让模型直接优化"人类觉得好"这个目标。**

---

## 🎮 强化学习速成：三分钟搞懂核心概念

> ❓ **问题**：RLHF 里的"强化学习"是什么？为什么不用监督学习？

在讲 RLHF 之前，我们需要理解什么是**强化学习（Reinforcement Learning, RL）**。

强化学习的核心框架非常简单：

```
┌──────────┐     动作      ┌──────────┐
│  智能体   │ ──────────→ │  环境     │
│ (Agent)  │              │(Environment)│
│          │ ←────────── │          │
└──────────┘    奖励/状态  └──────────┘

循环：
1. Agent 观察当前状态（State）
2. Agent 选择一个动作（Action）
3. Environment 返回一个奖励（Reward）+ 新状态
4. Agent 根据奖励调整策略，争取下次得更多奖励
```

生活中到处都是强化学习：

- **学骑自行车**：你的动作（蹬踏板、转向），环境反馈（摔了 = 差、骑稳了 = 好），你调整策略争取不摔
- **打游戏**：你的操作（走位、攻击），环境反馈（得分、升级），你调整策略争取得高分
- **训练宠物**：狗做了正确动作 → 给零食（正奖励），做了错事 → 大声说"No"（负奖励）

**关键区别：监督学习告诉你"标准答案是什么"，强化学习只告诉你"做得好不好"。**

这恰好是 SFT 和 RLHF 的区别：

```
SFT（监督学习）:
  输入: "什么是光合作用？"
  标准答案: "光合作用是植物……"
  → 模型学着输出和标准答案一样的文本

RLHF（强化学习）:
  输入: "什么是光合作用？"
  模型生成: "光合作用是……"
  奖励: 0.85（人类觉得挺好）
  → 模型学着生成"奖励更高"的文本，没有标准答案
```

这就是为什么 RLHF 更强大——**它不绑定特定答案，只优化"人类觉得好"这个目标**。

## 🏗️ RLHF 的三步走战略

> ❓ **问题**：RLHF 具体怎么实现？需要哪些组件？

OpenAI 在 InstructGPT 论文中提出的 RLHF 分三步：

```
┌─────────────────────────────────────────────────────────┐
│  Step 1: SFT（监督微调）                                 │
│  用指令-回答对训练一个基础模型                            │
│  → 得到 SFT 模型（昨天的内容）                           │
└──────────────────────┬──────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────┐
│  Step 2: 训练 Reward Model（奖励模型）                   │
│  让人类给不同回答打分排序                                 │
│  训练一个能预测"人类偏好"的模型                           │
│  → 得到 RM（Reward Model）                               │
└──────────────────────┬──────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────┐
│  Step 3: 用 PPO 强化学习优化 SFT 模型                    │
│  SFT 模型生成回答 → RM 给出奖励 → PPO 更新模型           │
│  → 得到最终的对齐模型                                    │
└─────────────────────────────────────────────────────────┘
```

Step 1 我们昨天已经做了。今天重点讲 Step 2 和 Step 3。

## 📊 Step 2: 奖励模型（Reward Model）— 教 AI 学会人类的品味

> ❓ **问题**：强化学习需要"奖励"，但谁来给奖励？每次都问人类太慢了吧？

没错，每次都问人类完全不现实——训练中模型要生成数百万个回答，不可能每个都让人类来评。

RLHF 的巧妙之处在于：**先训练一个"模仿人类品味"的模型，然后让这个模型自动给奖励**。

这就像你请了一位美食评论家吃了 1000 道菜、打了 1000 个分之后，你就了解了这位评论家的口味。以后新做一道菜，你自己就能预测他会打几分——不需要真的问他。

### 收集人类偏好数据

首先，让人类对同一个指令的多个回答进行排序：

```
指令: "解释什么是黑洞"

回答 A: "黑洞是天空中黑色的东西。"           → 排名第 3（太简略）
回答 B: "黑洞是宇宙中引力极强的区域，连光都逃不出来。  → 排名第 1（最好
         它是大质量恒星死亡后的产物。"
回答 C: "黑洞是密度无限大的奇点，会吞噬一切。"  → 排名第 2（还行但不完整）

人类偏好: B > C > A
```

收集大量这样的排序数据（InstructGPT 用了约 50K 条）。

### 训练奖励模型

奖励模型（Reward Model, RM）的架构很简单：**就是一个 LLM 去掉最后的语言模型头，换成一个输出标量的头**。

```
输入: "指令 + 回答" 的完整文本
输出: 一个标量分数（如 0.85）

      ┌──────────────┐
      │  Transformer  │
      │  (预训练权重)  │
      └──────┬───────┘
             ↓
      ┌──────────────┐
      │  Value Head   │  ← 新加的：Linear(d_model → 1)
      │  (线性层)     │
      └──────┬───────┘
             ↓
      奖励分数: 0.85
```

训练目标用**Bradley-Terry 排序损失**（也叫偏好损失）：

```
对于一对回答 (chosen, rejected)：

Loss = -log(σ(reward_chosen - reward_rejected))

其中 σ 是 sigmoid 函数

直觉：
- chosen 的奖励 > rejected 的奖励 → loss 小 → 好的 ✅
- chosen 的奖励 < rejected 的奖励 → loss 大 → 惩罚 ❌
- 差距越大 → loss 越小 → 更确信这个排序
```

翻译成人话：**让模型给"人类喜欢的回答"打高分，给"人类不喜欢的回答"打低分**。

## 🚀 Step 3: PPO 强化学习 — 让模型自己进化

> ❓ **问题**：有了奖励模型，怎么用它来优化 LLM？

现在我们有了两个模型：
- **SFT 模型**：能听指令，但回答质量有天花板
- **Reward Model**：能判断一个回答"有多好"

第三步就是让 SFT 模型不断生成回答，用 RM 打分，然后用**强化学习算法**更新 SFT 模型的参数，让它生成的回答得分越来越高。

### PPO（Proximal Policy Optimization）简介

PPO 是 OpenAI 在 2017 年提出的强化学习算法，全称"近端策略优化"。它解决的核心问题是：**怎么安全地更新模型，既学到新东西，又不走太远把旧知识搞崩？**

PPO 的核心思想用一个比喻来理解：

```
你在走一条山路，想到达山顶（最大奖励）：

❌ 普通梯度下降：
   每一步都朝着最陡的方向走 → 可能一步跨太远，直接掉下悬崖

✅ PPO：
   每一步都限制自己"不能偏离上一步太远" → 安全但稳定地前进
```

PPO 的关键公式（简化版）：

```
ratio = 新策略的概率 / 旧策略的概率
clipped_ratio = clip(ratio, 1-ε, 1+ε)  # 限制在 [1-ε, 1+ε] 范围内

objective = min(ratio × advantage, clipped_ratio × advantage)

其中：
- ratio > 1+ε → 新策略比旧策略更激进，但被 clip 住了
- ratio < 1-ε → 新策略比旧策略更保守，也被 clip 住了
- ε 通常设为 0.2 → 每次更新幅度不超过 ±20%
```

**翻译成人话：每一步更新都加一个"安全带"，防止模型走太远。**

### RLHF 的 PPO 训练流程

```
┌─────────────────────────────────────────────────────┐
│  每一轮训练（一个 batch）：                          │
│                                                     │
│  1. 从指令池中采样一批指令                           │
│     如 ["解释黑洞", "翻译句子", "写首诗", ...]       │
│                                                     │
│  2. SFT 模型（当前策略）对每个指令生成回答           │
│     输入: "解释黑洞"                                │
│     输出: "黑洞是引力极强的天体……"                  │
│                                                     │
│  3. Reward Model 给每个回答打分                      │
│     "黑洞是引力极强的天体……" → 0.82 分             │
│                                                     │
│  4. 计算 KL 惩罚（防止偏离 SFT 太远）               │
│     kl_penalty = KL(当前策略 || SFT 参考策略)       │
│     实际奖励 = RM 分数 - β × kl_penalty             │
│                                                     │
│  5. 用 PPO 更新 SFT 模型参数                        │
│     让模型以后生成这种高分回答的概率更大              │
│                                                     │
│  6. 重复 → 模型的回答越来越好                       │
└─────────────────────────────────────────────────────┘
```

### 为什么需要 KL 惩罚？

> ❓ **问题**：直接最大化 RM 分数不行吗？为什么要减去一个 KL 惩罚？

因为**奖励模型不完美**。如果你纯粹最大化 RM 分数，模型会找到 RM 的漏洞——生成一些 RM 给高分但人类觉得毫无意义的话。这叫**奖励作弊（Reward Hacking）**。

```
真实例子（假设）：

指令: "写一首关于春天的诗"

正常回答: "春风拂面柳丝长……"  → RM 给 0.7 分
奖励作弊: "spring spring spring spring spring……" → RM 可能给 0.9 分
```

模型发现 RM 对某些特殊模式给高分，就开始疯狂输出这种模式——**它学会了骗分，而不是真正变好**。

KL 惩罚的解决方案：**限制当前策略不能偏离原始 SFT 策略太远**。

```
实际奖励 = Reward Model 分数 - β × KL 散度

- KL 散度衡量"当前策略"和"SFT 策略"的差异
- β 是权重超参数（通常 0.01 ~ 0.1）
- 如果当前策略和 SFT 差异太大 → 惩罚很重 → 迫使模型在"变好"和"不偏离太远"之间找平衡
```

类比：KL 惩罚就像考试的"书写分"——你可以追求高分答案，但如果字迹太潦草（偏离正常文本太多），还是会被扣分。

## 📈 RLHF 的效果：为什么 ChatGPT 让人惊艳？

> ❓ **问题**：RLHF 的实际效果有多大？

OpenAI 的论文给出了非常清晰的对比：

```
人类评估员偏好率（InstructGPT 论文数据）:

对比                         人类偏好率
─────────────────────────────────────────
SFT 模型 vs 预训练模型        85% vs 15%
RLHF 模型 vs SFT 模型        73% vs 27%
RLHF 模型 vs GPT-3 (175B)    71% vs 29%

→ RLHF 后的 1.3B 模型比 175B 的 GPT-3 更受人类欢迎！
```

这说明：**对齐（Alignment）比规模（Scale）更重要**。一个经过 RLHF 的小模型，在用户体验上可以打败没有对齐的大模型。

## 🔍 PPO 的核心数学细节（进阶）

> ❓ **问题**：PPO 的更新公式具体长什么样？`advantage` 是什么？

对于想深入理解的读者，我们来拆解 PPO 的完整目标函数：

```
L_CLIP = E_t[min(ratio_t(θ) × A_t, clip(ratio_t(θ), 1-ε, 1+ε) × A_t)]

其中：
- θ 是模型参数
- ratio_t(θ) = π_θ(action|state) / π_old(action|state)
  → 新策略选择这个动作的概率 / 旧策略选择这个动作的概率
- A_t = 优势函数（Advantage）= "这个回答比平均水平好多少"
- ε ≈ 0.2
```

**优势函数 A_t 怎么算？**

```
A_t = reward_t - baseline

其中 baseline（基线）通常用 Value Function 估计：
- reward_t: 当前回答的 RM 分数
- baseline: "平均来说这个指令能得多少分"
- A_t > 0: 这个回答比平均好 → 鼓励这种回答
- A_t < 0: 这个回答比平均差 → 抑制这种回答
```

在我们的代码中，为了简化，我们用以下近似：

```
A_t ≈ reward_t（简化版，不做 baseline 估计）
```

这在教学演示中足够说明问题。

## 🧩 代码实现：从零实现 RLHF

1. **Reward Model 训练**：用人类偏好排序数据训练奖励模型

运行方式：
```bash
python3 rlhf.py
```

你将看到模型如何通过"人类偏好反馈"一步步提升回答质量。

## 🔑 关键洞察

1. **RLHF 的本质是"人类偏好优化"**——不是学标准答案，而是学"什么样的回答人类更喜欢"
2. **三步走：SFT → Reward Model → PPO**——每一步都解决上一步的局限
3. **Reward Model 是"人类品味的压缩"**——用数千条人类偏好数据训练一个能自动评分的模型
4. **PPO 是"带安全带的梯度下降"**——限制每次更新幅度，防止走太远
5. **KL 惩罚是"奖励作弊防御"**——不让模型钻 RM 的空子
6. **对齐 > 规模**——经过 RLHF 的小模型可以比没有对齐的大模型更受欢迎

---

## 📝 一句话总结

> RLHF 分三步走：先用 SFT 让模型听懂指令，再训练一个 Reward Model 学会人类的偏好品味，最后用 PPO 强化学习让模型直接优化"人类觉得好"这个目标——关键创新是用 Bradley-Terry 偏好损失训练 RM、用 PPO 的 clip 机制做安全更新、用 KL 惩罚防止奖励作弊，三重保障让模型既变好又不变坏。

## 📖 关键术语速查

| 术语 | 含义 |
|------|------|
| **RLHF** | Reinforcement Learning from Human Feedback，用人类反馈做强化学习 |
| **Reward Model (RM)** | 学习人类偏好的打分模型，给回答一个标量分数 |
| **PPO** | Proximal Policy Optimization，近端策略优化，带"安全带"的强化学习算法 |
| **Bradley-Terry 损失** | 偏好排序损失，让 RM 给"好的回答"打高分 |
| **KL 惩罚** | 限制当前策略和参考策略的 KL 散度，防止偏离太远 |
| **奖励作弊（Reward Hacking）** | 模型找到 RM 的漏洞，生成高分但无意义的内容 |
| **优势函数（Advantage）** | 衡量当前回答比"平均水平"好多少 |
| **对齐（Alignment）** | 让模型行为符合人类意图和价值观 |
