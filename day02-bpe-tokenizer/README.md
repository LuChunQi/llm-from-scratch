# Day 2 - Tokenization：文字怎么变成数字？

> **一句话总结：** Tokenization 是 LLM 处理人类语言的第一步——它把连续的文字切成一个个"词片"（token），然后映射成数字，让神经网络能够理解和处理。

---

## 🤔 为什么需要 Tokenization？

想象你在学一门完全不懂的外语。老师不会一开始就让你读整篇文章，而是先教你一个个单词。Tokenization 就是 LLM 的"识字课"——把一长串文字拆成它能消化的最小单元。

但是，LLM 不认识文字。它只懂数字（0 和 1）。所以 Tokenization 做了两件事：

1. **切分（Segmentation）：** 把 "我爱吃火锅" 拆成 `["我", "爱", "吃", "火锅"]`
2. **编码（Encoding）：** 把每个词片映射到一个整数 ID，比如 `["我"→234, "爱"→567, "吃"→89, "火锅"→1023]`

最终喂给模型的就是一串整数：`[234, 567, 89, 1023]`

### 为什么不一个字一个字地切？

一个字一个字切（Character-level）听起来最简单，但问题很大：

- **序列太长了！** "The quick brown fox jumps over the lazy dog" 一个字母一个字母切就有 43 个 token
- **含义丢失。** 单个字母 "t" 没有任何含义，"th" 也几乎没有，但 "the" 是一个完整的词
- **模型学起来很困难。** 它需要自己学会 "q-u-i-c-k" 连在一起才表示 "快"

### 为什么不一个词一个词地切？

那一个词一个词切（Word-level）呢？也有问题：

- **词表太大！** 英语有几十万个词，中文更夸张——汉语大词典收了 37 万个词
- **无法处理新词。** 训练时没见过的词（如新出现的网络用语 "yyds"）就完全不认识
- **形态变化多。** "run"、"running"、"ran" 是三个不同的词，但语义相近，却要占三个词表位置

### Goldilocks 的故事：不大不小，刚刚好

就像金发姑娘选择粥的温度一样，我们需要一种 "subword"（子词）级别的切分策略：

- 常见词保持完整：`"the" → ["the"]`
- 罕见词拆成常见片段：`"unhappiness" → ["un", "happi", "ness"]`
- 从未见过的也能处理：`"chatgptification" → ["chat", "g", "pt", "ification"]`

这就是 **BPE（Byte Pair Encoding）** 的核心思想！

---

## 🔧 BPE 算法详解

### 直觉理解：合并高频组合

想象你在做文字拼图。一开始，每个字母都是独立的拼图块：

```
初始状态：l o w _ n e w e r _ l o w e r _ l o w e s t
```

**Step 1：** 数一数，哪些相邻的字母对出现最频繁？

```
"lo" 出现了 3 次（low, lower, lowest）
"ow" 出现了 3 次
"er" 出现了 2 次（newer, lower）
...
```

**Step 2：** 把出现最多的 "lo" 合并成一个新符号：

```
合并后：lo w _ n e w e r _ lo w e r _ lo w e s t
```

**Step 3：** 再数一遍，现在 "low" 出现了 3 次，最频繁，合并！

```
合并后：low _ n e w e r _ low e r _ low e s t
```

**Step 4：** 继续合并 "er"...

```
合并后：low _ n e w er _ low er _ low e s t
```

就这样不断合并，直到达到你想要的词表大小。**合并的次数 = 词表大小 - 初始词表大小**。

### 为什么要从 "字节" 开始？

现代 BPE（如 GPT 系列用的）有一个聪明的做法：**从字节级别开始**。

- 初始词表只有 256 个——就是所有可能的字节值（0x00 到 0xFF）
- 这意味着 **任何语言的任何文本都能处理**，不管中英日韩
- 甚至能处理代码、emoji、特殊字符——因为它们归根结底都是字节

这就像乐高积木，最基本的零件只有那么几种，但可以拼出任何形状。

### 算法步骤总结

```
1. 准备训练语料，每个词拆成单个字节序列
2. 统计所有相邻 token 对的出现频率
3. 找到频率最高的 token 对 (A, B)
4. 把所有 AB 合并成新 token AB
5. 把 AB 加入词表，记录合并规则
6. 重复 2-5，直到词表达到目标大小（如 50000）
```

### 编码新文本（推理时）

当你拿到一段新文本时，**按顺序回放**训练时学到的合并规则：

```python
text = "lowest"
# 字节级开始: ['l', 'o', 'w', 'e', 's', 't']
# 合并规则 #1: l+o → lo  → ['lo', 'w', 'e', 's', 't']
# 合并规则 #5: lo+w → low → ['low', 'e', 's', 't']
# 合并规则 #12: e+s → es → ['low', 'es', 't']
# 合并规则 #20: es+t → est → ['low', 'est']
# 最终: ['low', 'est']
```

顺序很重要！先学的规则先应用。

## 🌍 中文 Tokenization 的特殊性

### 中文不是空格分割的

英文天然有空格分词：`"I love cats"` → `["I", "love", "cats"]`

中文没有空格：`"我喜欢猫"` → 该怎么切？

BPE 会自己学会最优的切分方式。在 GPT-4 的 tokenizer 中，中文通常被切成 1-2 个汉字一个 token。这也是为什么同样的内容，中文比英文消耗更多 token：

```
英文: "I love you" → 3 tokens
中文: "我爱你"    → 3-5 tokens（取决于具体 tokenizer）
```

### 一个有趣的例子

```
"ChatGPT很厉害" 
可能的切分: ["Chat", "G", "PT", "很", "厉害"]
```

注意 "Chat" 和 "GPT" 被拆开了！因为训练语料中 "ChatGPT" 可能出现得不够多，没有被作为一个整体加入词表。而 "G" 和 "PT" 是常见的子串（"G" 在很多英文单词中，"PT" 可能和 "PTSD"、"VPT" 等共享）。

## 📊 不同 Tokenizer 的对比

| Tokenizer | 词表大小 | 特点 |
|-----------|---------|------|
| GPT-2 BPE | 50,257 | 字节级 BPE，英文友好 |
| GPT-4 (cl100k_base) | 100,256 | 更大的词表，多语言更好 |
| LLaMA (SentencePiece) | 32,000 | SentencePiece BPE |
| Qwen | 151,643 | 中文优化，词表很大 |
| Claude | ~100,000 | 多语言优化 |

词表越大，常见词越能保持完整，token 效率越高，但模型的 embedding 层也会更大。

## 💡 Key Insights

1. **Tokenization 不是简单的"分词"，而是一种数据压缩。** 它把文本压缩成更少的 token，每个 token 携带更多信息。

2. **BPE 的本质是贪心合并。** 每次选频率最高的相邻对合并，简单粗暴但效果很好。

3. **字节级 BPE 是一切的基础。** 256 个字节 = 所有语言、所有字符的通用起点。

4. **合并顺序决定了切分结果。** 不同的训练语料会产生不同的合并顺序，也就产生不同的 tokenizer。

5. **Tokenizer 是 LLM 的"世界观"。** 模型能"看到"什么，完全取决于 tokenizer 怎么切。一个好的 tokenizer 能让模型事半功倍。

## 🔑 关键术语速查

| 术语 | 解释 |
|------|------|
| **Token** | 文本被切分后的最小单元，可以是词、子词或字符 |
| **Tokenization** | 把文本转换成 token 序列的过程 |
| **Vocabulary（词表）** | 所有可能的 token 的集合，每个 token 对应一个唯一 ID |
| **BPE (Byte Pair Encoding)** | 一种子词分词算法，通过不断合并高频字节对来构建词表 |
| **Subword** | 介于字符和完整词之间的单元，如 "un"、"happi"、"ness" |
| **Merge Rule** | BPE 学习到的合并规则，记录了哪些 token 对应该合并 |
| **Byte-level BPE** | 以 256 个字节为初始词表的 BPE 变体（GPT 系列使用） |
| **SentencePiece** | Google 开发的分词工具，支持 BPE 和 Unigram 两种算法 |
| **tiktoken** | OpenAI 开源的高效 BPE tokenizer（用于 GPT-4） |
| **Token Efficiency** | 用更少的 token 表达同样的内容，越高效越好 |
