## 一、RNN — "让网络拥有记忆"

> ❓ **问题**：前馈网络每次只看一个词，完全不知道前面说了什么。怎么让它"记住"历史？

### 1.1 普通神经网络的局限

普通的前馈神经网络（Feedforward Neural Network）处理输入时，**每个输入都是独立的**：

```
输入 "我" → 网络 → 输出
输入 "爱" → 网络 → 输出    ← 完全不知道前面有个 "我"
输入 "你" → 网络 → 输出    ← 完全不知道前面有 "我爱"
```

这就像一个 **没有短期记忆的人**，每个字对他来说都是孤立的。

### 1.2 RNN 的解法：把上一步的输出喂给下一步

RNN 引入了一个 **隐藏状态（hidden state）**，它像一条"信息传送带"，把前面的信息传递到后面：

```
时间步 t=1:  h₁ = f(x₁, h₀)     ← h₀ 是初始状态（通常是零向量）
时间步 t=2:  h₂ = f(x₂, h₁)     ← h₁ 携带了 x₁ 的信息
时间步 t=3:  h₃ = f(x₃, h₂)     ← h₂ 携带了 x₁, x₂ 的信息
...
```

用更直观的方式理解：

```
想象你在听别人讲故事，每听到一个词，你脑子里就更新一次"当前理解"。
这个"当前理解"就是隐藏状态 h。
每一步，你把新的词和之前的"当前理解"结合起来，形成新的"当前理解"。
```

### 1.3 RNN 的数学形式

对于时间步 t：

```
hₜ = tanh(Wₓₕ · xₜ + Wₕₕ · hₜ₋₁ + bₕ)
yₜ = Wₕᵧ · hₜ + bᵧ
```

其中：
- `xₜ`：当前输入（比如当前词的向量）
- `hₜ₋₁`：上一步的隐藏状态
- `Wₓₕ`：输入到隐藏的权重矩阵
- `Wₕₕ`：隐藏到隐藏的权重矩阵（这就是"记忆"的核心）
- `tanh`：激活函数，把值压缩到 [-1, 1]
- `yₜ`：当前输出

### 1.4 关键特点

- **权重共享**：所有时间步使用同一组权重 `Wₓₕ, Wₕₕ, Wₕᵧ`。就像你用同一个大脑处理每一个字，而不是每个字换一个脑。
- **任意长度**：可以处理任意长度的序列（理论上）。
- **串行处理**：必须先算 h₁，再算 h₂，再算 h₃……**不能并行**。

## 二、RNN 的致命缺陷 — "传话游戏"

> ❓ **问题解决了？** RNN 确实能"记住"前面的信息了。但当句子很长的时候，还记得住吗？

### 2.1 梯度消失：信息在传递中衰减

还记得小时候玩的 **传话游戏** 吗？

```
第 1 个人听到："明天下午三点在图书馆开会"
第 2 个人传："明天下午三点在图书馆..."
第 3 个人传："明天下午三点..."
...
第 10 个人听到："明天...什么？"
```

RNN 就是在玩这个游戏。当序列很长时，**梯度在反向传播中会不断乘以同一个矩阵**：

```
∂L/∂W = ... × Wₕₕ × Wₕₕ × Wₕₕ × ... × Wₕₕ
```

- 如果 `Wₕₕ` 的特征值 < 1：梯度指数级缩小 → **梯度消失**（前面什么信息都忘了）
- 如果 `Wₕₕ` 的特征值 > 1：梯度指数级放大 → **梯度爆炸**（训练直接崩溃）

**实际中，梯度消失更常见。** 结果就是 RNN 的"记忆"大约只能维持 10-20 个时间步。

### 2.2 一个直观的例子

```
句子："我 出生 在 北京 ， 在 那里 长大 ， 上 了 小学 和 中学 ，
       后来 去 上海 读 大学 ， 毕业 后 去 了 深圳 工作 。"

问题：这个人出生在哪里？    → 北京（在句首，RNN 记不住 ✗）
问题：这个人现在在哪里工作？  → 深圳（在句尾，RNN 容易记住 ✓）
```

### 2.3 串行计算：无法并行

RNN 的计算依赖关系：

```
h₁ → h₂ → h₃ → h₄ → ... → hₜ
```

要计算 h₄，必须先算 h₁, h₂, h₃。这种 **严格的顺序依赖** 意味着：

- **无法利用 GPU 的并行能力**：GPU 擅长同时做大量计算，但 RNN 只能一步步算
- **训练速度慢**：长序列的训练非常耗时
- **推理也慢**：即使是在推理阶段，也只能一个 token 一个 token 地生成

> 🤔 **RNN 记不住长距离信息，计算还慢。怎么办？能不能让它"记性更好"？**

---

## 三、LSTM — "给传话游戏加上笔记本"

### 问题驱动的灵感

RNN 的信息靠隐藏状态一步步传，传着传着就丢了。那能不能给 RNN 配一个"笔记本"？重要的信息直接抄下来，不用只靠嘴巴传。

1997 年，Hochreiter 和 Schmidhuber 基于这个思路提出了 **LSTM**（Long Short-Term Memory）。

### 3.1 LSTM 的核心思想

> 与其让信息在隐藏状态中不断被"稀释"，不如给 RNN 一个 **专门的记忆通道**，让它可以选择性地记住或遗忘信息。

LSTM 引入了三个"门"（Gate）：

```
遗忘门（Forget Gate）：决定从长期记忆中丢弃什么
输入门（Input Gate）：  决定什么新信息存入长期记忆
输出门（Output Gate）：  决定从长期记忆中输出什么
```

### 3.2 LSTM 的内部结构

```
                    ┌─────────────────────────────────┐
                    │           LSTM Cell              │
                    │                                  │
  cₜ₋₁ ───────────►│─ × ─── + ──────────────────────►│──► cₜ (细胞状态)
                    │  │     ↑                        │
                    │  │     │                        │
                    │ 遗忘   输入                      │
                    │ 门     门                        │
                    │  │     │                        │
  hₜ₋₁ ──┬────────►│  │     │      ┌──输出门──┐      │
          │         │  │     │      │          │      │
  xₜ ────┤────────►│  ↓     ↓      ↓          ↓      │
          │         │ σ+×   σ+×   tanh        σ       │
          │         │                                  │
          │         │         × ──────────────►│──► hₜ (隐藏状态)
          │         └─────────────────────────────────┘
```

更精确地：

```python
# 遗忘门：决定忘记多少旧记忆
fₜ = sigmoid(Wf · [hₜ₋₁, xₜ] + bf)

# 输入门：决定接收多少新信息
iₜ = sigmoid(Wi · [hₜ₋₁, xₜ] + bi)

# 候选记忆：新的"可能记住"的内容
c̃ₜ = tanh(Wc · [hₜ₋₁, xₜ] + bc)

# 更新细胞状态：旧记忆 × 遗忘门 + 新信息 × 输入门
cₜ = fₜ * cₜ₋₁ + iₜ * c̃ₜ

# 输出门：决定输出什么
oₜ = sigmoid(Wo · [hₜ₋₁, xₜ] + bo)

# 最终隐藏状态
hₜ = oₜ * tanh(cₜ)
```

### 3.3 为什么 LSTM 更好？

**细胞状态 cₜ 是一条"高速公路"**：

```
cₜ = fₜ * cₜ₋₁ + iₜ * c̃ₜ
       ↑                ↑
    保留旧记忆       加入新记忆
```

- 如果遗忘门 `fₜ ≈ 1`，信息可以 **几乎无损地** 从 c₁ 传到 c₁₀₀
- 这就像在传话游戏里给每个人发了一个笔记本，重要的信息可以直接抄下来，不用只靠嘴巴传

### 3.4 但 LSTM 也没能彻底解决问题

| 问题 | LSTM 改善了？ | 完全解决？ |
|------|:---:|:---:|
| 长距离依赖 | ✅ 好了很多 | ❌ 超长序列还是会衰减 |
| 并行计算 | ❌ | ❌ 仍然串行 |
| 计算效率 | ❌ | ❌ 比简单 RNN 更慢（参数更多） |
| 可解释性 | ❌ | ❌ 门控机制还是黑盒 |

> 🤔 **LSTM 缓解了"记不住"的问题，但串行计算的根本矛盾依然存在。** 不过在实际应用中，人们已经迫不及待地用 LSTM 去做翻译了——这又暴露了一个新问题……

## 四、Seq2Seq — "翻译官的困境"

### 问题驱动：LSTM 能记住上下文了，但怎么做"翻译"？

翻译不是理解一个句子就够了，而是要把一个语言序列**转换**成另一个语言序列。这需要一种全新的架构：**Encoder-Decoder**（编码器-解码器）。

### 4.1 编码器-解码器结构

```
编码器（LSTM）: 逐个读入源语言句子，最后得到一个"上下文向量" c
                ↓
解码器（LSTM）: 基于上下文向量 c，逐个生成目标语言句子

例：中文 → 英文
编码器: 我 → 爱 → 编程 → [上下文向量 c]
解码器: c → I → love → coding
```

看起来很优雅对吧？但有一个致命的瓶颈……

### 4.2 瓶颈问题

编码器不管输入句子多长，最后都要压缩成 **一个固定长度的向量 c**！

```
"我爱你" → c (一个向量) → "I love you"          ← 短句，c 够用 ✅

"今天天气真好我想出去玩但是明天要考试所以还是在家复习吧"
         → c (同一个大小的向量) → "The weather is nice..."   ← 长句，c 不够用 ❌
```

这就像要求你 **把一整本书总结成一句话**，然后别人根据这句话来复述整本书。信息损失巨大。

> 🤔 **无论编码器用 RNN 还是 LSTM，最终都只能输出一个固定长度的向量。长句子的信息根本装不下。** 怎么打破这个瓶颈？

---

## 五、Attention — "别再压缩了，按需取用！"

### 问题驱动的灵光一现

既然把整个句子压成一个向量会丢信息，那——**干脆不压缩了！** 让解码器在生成每个词的时候，都能"回头看"完整的输入句子，自己找到最相关的部分。

2015 年，Bahdanau 等人提出了这个革命性的想法，它就是 **Attention**。

### 5.1 Attention 做了什么？

```
解码器生成 "love" 时：
  - 关注 "爱" 的程度 = 0.8  ← 最相关！
  - 关注 "我" 的程度 = 0.1
  - 关注 "编程" 的程度 = 0.1

解码器生成 "I" 时：
  - 关注 "我" 的程度 = 0.9  ← 最相关！
  - 关注 "爱" 的程度 = 0.05
  - 关注 "编程" 的程度 = 0.05
```

不再用一个向量承载所有信息，而是 **每一步按需提取**。就像考试时允许你翻书——你不需要把整本书背下来，只需要知道去哪一页找答案。

### 5.2 Attention 的数学本质

Attention 本质上就是一个 **加权求和**：

```
Attention(query, keys, values) = Σ (相似度(query, keyᵢ) × valueᵢ)
```

具体步骤：

```
1. 计算查询(query)和每个键(key)的相似度 → 得到分数
2. 用 softmax 把分数变成概率分布 → 得到注意力权重
3. 用权重对值(value)加权求和 → 得到注意力输出
```

一个类比：

```
你去图书馆找书（query = "Python 入门"）：
1. 看每本书的书名/标签（key），计算和你的需求的相似度
2. 相关度排序，最相关的书权重最高（softmax）
3. 从每本书中提取你需要的信息（value），按权重汇总
```

### 5.3 从 Attention 到 Self-Attention

Attention 最初是给"翻译"用的（解码器看编码器的输出）。但很快有人想到：

> 如果 Attention 让模型能"看别人"，那能不能让一个序列里的每个词也"看自己人"？让每个词都直接看到句子里所有其他词？

这就是 **Self-Attention**。它彻底绕开了 RNN 的链式传递：

```
RNN：信息沿链条传播，像绿皮火车，每站都停
     北京 → 石家庄 → 郑州 → 武汉 → 长沙

Self-Attention：每个位置一步直达，像坐飞机
     北京 ✈ 长沙，直达！
```

### 5.4 根本性区别一览

| 特性 | RNN/LSTM | Self-Attention |
|------|----------|----------------|
| 信息传播路径 | 链式（必须经过中间节点） | 直接（任意两个位置一步直达） |
| 长距离依赖 | 信息衰减 | **无衰减**（距离平等） |
| 并行性 | 串行 | **完全并行**（所有位置同时计算） |
| 计算复杂度 | O(n) 串行 | O(n²) 但可并行 |
| 位置信息 | 隐式（通过顺序） | 需要显式位置编码 |

> 🤔 **等等——Attention 这么好，而且它根本不依赖 RNN 的链式结构。那我们还需要 RNN 吗？**

## 六、Transformer — "既然不需要，那就扔掉！"

### 历史的转折点

2017 年，Google 的论文 **"Attention Is All You Need"** 给出了一个大胆的回答：

> **RNN 完全不需要！Attention 本身就够了！**

他们提出了 **Transformer**，一个纯 Attention 架构。今天你听过的所有大模型——GPT、BERT、LLaMA、Claude——全部基于它。

Transformer 的关键组成：
1. **Self-Attention**：捕获任意距离的依赖关系
2. **Multi-Head Attention**：多组注意力并行，从不同角度理解句子
3. **位置编码**：弥补 Attention 本身没有位置信息的缺陷
4. **Feed-Forward Network**：在每个位置做非线性变换
5. **Layer Normalization + Residual Connection**：让深层网络能训练

### 三大缺陷，全部解决

```
RNN 的三个老问题：
  1. 长距离信息衰减 → Attention 直达，无衰减 ✅
  2. 无法并行计算 → Attention 完全并行 ✅
  3. 固定大小瓶颈 → Attention 动态按需取用 ✅
```

## 📌 一句话总结

> RNN 像传话游戏，信息一步步传递必然衰减；LSTM 加了笔记本缓解但仍串行；Seq2Seq 把长句子压成一个向量，信息装不下；Attention 说"别压缩了，按需取用"——最终 Transformer 把 RNN 彻底扔掉，开启了新纪元。

## 🔑 关键术语速查

| 术语 | 含义 |
|------|------|
| **RNN** | 循环神经网络，通过隐藏状态在时间步间传递信息 |
| **Hidden State** | RNN 的"记忆"，每步更新的向量 |
| **梯度消失** | 反向传播中梯度不断缩小，导致长距离依赖无法学习 |
| **梯度爆炸** | 反向传播中梯度不断增大，导致训练不稳定 |
| **LSTM** | 长短期记忆网络，通过门控机制缓解梯度消失 |
| **Cell State** | LSTM 的"长期记忆通道"，信息可以无损流过 |
| **门控机制** | 遗忘门、输入门、输出门，控制信息的流动 |
| **Seq2Seq** | 编码器-解码器结构，用于翻译等序列转换任务 |
| **Attention** | 让模型能"回头看"输入序列，动态聚焦相关部分 |
| **Self-Attention** | 序列内部的位置互相注意，捕获内部依赖关系 |
| **Transformer** | 纯 Attention 架构，抛弃了 RNN 的串行结构 |
